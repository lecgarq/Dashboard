export interface RawFolder {

  status: "ok" | "partial" | "failed";
  reason?: string;
}

export interface CrawlOptions {
  dryRun: boolean;                    // when true: no DB writes (caller responsible)

<task type="auto">
  <name>Task 1: Implement folderCrawl.ts with BFS + pLimit + dryRun param</name>
  <files>lib/acc/folderCrawl.ts</files>
  <action>
Create `lib/acc/folderCrawl.ts` implementing the interfaces above. Critical rules:

1. **BFS, not recursion.** Use an explicit `queue: Array<{ folderId, parentId, parentPath }>` and a `while (queue.length > 0)` loop. NEVER recurse into `scanFolder()` — depth can exceed Node's stack.

2. **pLimit per project.** `import pLimit from "p-limit"; const limit = pLimit(options.pLimitConcurrency ?? 5);`. Drain up to `concurrency` items from the queue per tick, fetch in parallel under the limit, append discovered children to the queue. Track elapsed time at the top of each loop iteration.

3. **Time budget.** Read `elapsedMs = Date.now() - startedAt` each iteration. If `>= hardCapMs (default 900_000)`: break the loop, set `status='partial'`, set `reason='hard_cap_exceeded'`. If `>= softCapMs (default 300_000)` and not yet warned: `console.warn` once. Both caps logged with project id.

4. **Retries.** Use `fetchWithRetry` from `lib/server/acc-admin.ts` for every APS call — do NOT duplicate retry logic. Per-call try/catch: on persistent failure (after fetchWithRetry exhausts), set project status='partial' and continue with whatever was crawled.

5. **Endpoint discipline:**
   - First call: top folders (`/project/v1/hubs/{hubId}/projects/{projectIdForDM}/topFolders`).
   - Recurse via folder contents (`/data/v1/projects/{projectIdForDM}/folders/{id}/contents?filter[type]=folders`).
   - Permissions: AFTER the BFS completes, fetch permissions for every discovered folder. Use the SAME `pLimit(5)`. **URL uses `projectIdForPerms` (bare UUID — already b.-stripped by caller).** Apply `permissions.filter(p => p.subjectType === "ROLE")` at the parse boundary; discard USER permissions.

6. **dryRun param.** When `options.dryRun === true`: the function still returns `folders` and `permissions` arrays in memory but the CALLER is responsible for skipping DB writes. The library NEVER touches Prisma directly — keep it pure for testability. (Plan 04 will add an `extractAndPersistFolders()` wrapper that consumes this and writes the DB.)

7. **fullPath computation:** Each folder's `fullPath = parentPath + "/" + name`. Root folders have `parentPath = ""` (so fullPath becomes `/<name>`).

Export everything declared in the interface block. Add JSDoc comments referencing the b.-prefix distinction at the function signature.
