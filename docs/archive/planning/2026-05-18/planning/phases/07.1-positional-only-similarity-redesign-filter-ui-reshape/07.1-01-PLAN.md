  <action>
Implement per RESEARCH §Code Examples #1 (lines 316–404 of 07.1-RESEARCH.md). Pure module, zero non-pure deps, type-only import from `./userSimilarity`.

Algorithm:
1. Compute per-dim max sharedCount → normalize each edge's contribution to [0..1].
2. Compose per-pair total: sum over enabled dims of (norm * simStr[dim]), capped at maxStrength (default 5).
3. Drop pairs with composed strength <= pairStrengthCutoff (default 0).
4. Drop pairs whose endpoints aren't in nodeIndex.
5. Top-K cap: per-user adjacency, sort by strength desc, take top K; UNION the per-user sets (symmetric — keep edge if either endpoint's top-K contains it). K=0 means unbounded.
6. Pack into Int32Array (pairs) + Float32Array (strengths) aligned by index.

Export:
- type `ForceLinkBuffer` { pairs: Int32Array; strengths: Float32Array; pairCount: number }
- type `StrengthInput` (mirror RESEARCH signature: edges, simStr (Record&lt;SimilarityDim, number&gt;), pairStrengthCutoff?, topK?, nodeIndex (ReadonlyMap), maxStrength?)
- function `buildForceLinkBuffer(input: StrengthInput): ForceLinkBuffer`

Pitfall 2 (RESEARCH §Pitfalls): this module returns ONLY force-link buffer; render-link prefix concatenation is the renderer's job (Plan 07.1-04). Document this contract in a top-of-file comment.

Run `npx vitest run lib/acc/similarityForceModel.test.ts` — all cases pass. Run `npx tsc --noEmit` — clean.
