  <files>app/(dashboard)/users/graphRenderers.ts, app/(dashboard)/users/accGraphOrganicLayout.worker.ts</files>
  <action>
**Root cause:** In `CosmosGraphRenderer.draw()`, link buffers re-upload only when `linkCount !== this.lastLinkCount`. During drag, count is unchanged, so Cosmos retains stale link spatial structures while node positions move — endpoints visually detach.

**Fix:**
1. In `CosmosGraphRenderer.draw()` when `positionsChanged && nodeCount > 0` and `frame.links` exists, also call `this.graph.setLinks(buildLinkBuffer(frame.links))` regardless of `linkCount` equality during interactive frames (`frame.isInteracting === true`).
2. Throttle: track `this.lastLinkUploadAt`; skip if `Date.now() - lastLinkUploadAt < 33` (avoid GPU upload churn during 60fps drag).
3. In `accGraphOrganicLayout.worker.ts` drag handler, add a one-line comment confirming `renderLinks` is stable across drag (no recompute needed).

**Why this approach:** Cosmos has no built-in distance culling for links; positions are pre-scaled to ±1000 (well within Float32 precision). Stale link spatial-structure references are the only remaining cause.
  </action>

    <automated>npx tsc --noEmit</automated>
    Manual smoke: `npm run dev`, navigate to /users, drag a node 800+ pixels from its cluster, confirm visible connection lines stay attached throughout. (Verified in Task 5 checkpoint.)
  </verify>
  <done>
TypeScript compiles. CosmosGraphRenderer.draw() re-uploads link buffer on every interactive frame with a 33ms throttle. Worker drag handler comment clarifies link stability invariant.
  </done>
