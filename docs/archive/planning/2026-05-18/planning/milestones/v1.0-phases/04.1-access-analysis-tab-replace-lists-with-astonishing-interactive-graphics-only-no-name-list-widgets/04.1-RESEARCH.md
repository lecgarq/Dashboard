## Summary

This is a UI-only re-skin of four existing dashboard widgets. All data, analytics, contexts, drill-down panel, CSV export, drag-and-drop, and routing are already in place from Phase 4 — the work is purely swapping table-based widget bodies for SVG/d3 + framer-motion visualizations while keeping the existing widget-registry contract (id, title, span, `WidgetCommonProps` shape) and reusing `useFindings()` and `useSelection()` hooks.

The stack is fully locked: SVG + `d3-hierarchy` (pack/treemap) + `d3-time` + `d3-scale` + `framer-motion` 12.35 (already a dep). No new heavyweight libraries. Cosmos-aesthetic match comes from a single shared `dashboardTokens.ts` module (palette + spring tokens) consumed by every widget — not from a different rendering engine.

The two non-trivial risks are: (1) animating diffs without re-mount jank, which `framer-motion` `<AnimatePresence>` + `layoutId` solves cleanly; and (2) the `selectionContext` `SelectedFinding` discriminated union currently only carries `junk | duplicate | outlier | role | null` — admin and day-of-join clicks need either new union members or a normalization layer, and that decision must be made in planning before any widget code lands.

**Primary recommendation:** Wave 0 ships `dashboardTokens.ts` (palette + spring tokens + reduced-motion helper) AND extends `SelectedFinding` to cover `admin` and `day` selections AND adds skeleton primitives. Wave 1 ships the four widget rewrites in parallel, each replacing one `widgets/*Widget.tsx` file in place. Wave 2 reviews the five existing graphical widgets for token consistency and ships a polish pass only where the diff is visible.

### Pattern 1: d3-layout-as-data + framer-motion-as-renderer
**What:** Use d3 as a *pure layout function* that returns coordinates; render the result as JSX SVG elements wrapped in `motion.*` for animation. Never let d3 mutate the DOM directly.
**When to use:** All four redesigned widgets.
**Example (bubble cluster):**
```tsx
// app/(dashboard)/users/dashboard/widgets/RecommendationsWidget.tsx
"use client";
import { useMemo } from "react";
import { hierarchy, pack } from "d3-hierarchy";
import { motion, AnimatePresence } from "framer-motion";
import { useFindings } from "../findingsContext";
import { useSelection } from "../selectionContext";
import { SEVERITY_COLOR, BUBBLE_SPRING } from "./_shared/dashboardTokens";

const W = 600, H = 360;

export function RecommendationsWidget() {
  const { junkFindings, duplicateFindings } = useFindings();
  const { setSelected, selected } = useSelection();

  const layout = useMemo(() => {
    const root = hierarchy({
      children: [
        { name: "junk",      children: junkFindings.map((f) => ({ ...f, _kind: "junk", value: f.affectedMembers.length || 1 })) },
        { name: "duplicate", children: duplicateFindings.map((f) => ({ ...f, _kind: "duplicate", value: f.affectedMembers.length || 1 })) },
      ],
    }).sum((d: any) => d.value ?? 0);
    return pack().size([W, H]).padding(6)(root).leaves();
  }, [junkFindings, duplicateFindings]);

  return (
    <svg viewBox={`0 0 ${W} ${H}`} role="img" aria-roledescription="severity bubble cluster">
      <AnimatePresence>
        {layout.map((node: any) => (
          <motion.circle
            key={`${node.data._kind}:${node.data.role ?? node.data.roleA}`}
            layoutId={`${node.data._kind}:${node.data.role ?? node.data.roleA}`}
            initial={{ opacity: 0, scale: 0.4 }}
            animate={{ opacity: 1, scale: 1, cx: node.x, cy: node.y, r: node.r }}
            exit={{ opacity: 0, scale: 0.4 }}
            transition={BUBBLE_SPRING}
            fill={SEVERITY_COLOR[node.data.severity ?? "MEDIUM"]}
            tabIndex={0}
            onClick={() => setSelected({ kind: node.data._kind, finding: node.data })}
            aria-label={`${node.data.severity ?? "MEDIUM"} severity, ${node.data.role ?? node.data.roleA}, ${node.data.value} members`}
          />
        ))}
      </AnimatePresence>
    </svg>
  );
}
// Source pattern: framer-motion AnimatePresence + layoutId — https://motion.dev/docs/react-animate-presence
// d3-hierarchy pack() — https://d3js.org/d3-hierarchy/pack
```

### Pattern 2: Single shared token module
**What:** One file (`_shared/dashboardTokens.ts`) exports `SEVERITY_COLOR`, `NEUTRAL`, `HIGHLIGHT`, spring presets (`BUBBLE_SPRING`, `CELL_SPRING`, `ORBIT_SPRING`), and a `getReducedMotionTransition(spring)` helper that returns a `duration: 0` config when `prefers-reduced-motion: reduce`. Light/dark variants resolved via `useTheme()` from `next-themes`.
**When:** Imported by every widget. Changing a token here propagates to all four — this is the lever the planner uses for "consistency" reviews of the existing five graphical widgets.
**Example token shape:**
```ts
// app/(dashboard)/users/dashboard/widgets/_shared/dashboardTokens.ts
import type { Transition } from "framer-motion";

// Light theme — translated from Cosmos canvas backgroundColor "#F8F7F4" + shadcn destructive #EF4444
export const SEVERITY_COLOR_LIGHT = {
  HIGH:   "#EF4444",
  MEDIUM: "#F59E0B",
  LOW:    "#3B82F6",
} as const;

// Dark theme — Cosmos-leaning glow palette
export const SEVERITY_COLOR_DARK = {
  HIGH:   "#FF6B6B",
  MEDIUM: "#FFB454",
  LOW:    "#5DADE2",
} as const;

export const BUBBLE_SPRING: Transition = { type: "spring", stiffness: 180, damping: 22, mass: 1 };
export const CELL_SPRING: Transition   = { type: "spring", stiffness: 220, damping: 26, mass: 1 };
export const ORBIT_SPRING: Transition  = { type: "spring", stiffness: 90,  damping: 14, mass: 1.4 };

export const HOVER_OPACITY_DIM = 0.4;
export const HOVER_OPACITY_FOCUS = 1.0;
```

### Pattern 3: Per-widget keyboard nav island
**What:** Each widget is a focusable region. Tab moves widget-to-widget (the SortableWidget Card already has tabIndex). Inside a widget, arrow keys move between interactive shapes; Enter dispatches `setSelected(...)`. Implement with a single `onKeyDown` on the widget root and an internal `focusIndex` state.
**When:** All four redesigned widgets.

### Pattern 4: Selection-aware spotlight
**What:** When `selected` matches a member/role this widget's element relates to, that element animates to `opacity: 1, scale: 1.04, filter: drop-shadow(...)`; siblings animate to `opacity: HOVER_OPACITY_DIM`. Cross-widget linking falls out for free because every widget reads `useSelection()`.
**When:** All four redesigned widgets + (optionally) heatmap and flow during the polish pass.

### Anti-Patterns to Avoid

- **d3 selecting into the DOM:** `d3.select("svg").selectAll("circle").data(...)` fights React's reconciliation and breaks framer-motion's `layoutId` tracking. Use d3 only for layout math; render with JSX.
- **Recomputing layout in render:** Wrap every d3 layout call in `useMemo` keyed by the input data. Layout cost grows with element count and re-running on every render at 60fps tanks the spring.
- **Animating SVG attributes via React state:** Use `motion.circle cx={...} cy={...}` (framer-motion intercepts attribute animation), not `setState({ cx })`. Prevents per-frame React reconciliation.
- **`fixed`-sized SVG:** Use `viewBox` + `preserveAspectRatio="xMidYMid meet"` and let CSS size the container. Card heights vary at the 1280px grid breakpoint (per Phase 4 Pitfall 2: heights are pinned per widget).
- **Per-widget palette duplication:** Don't hard-code `#EF4444` inside `OutlierCombosWidget`. Always import from `dashboardTokens.ts`.
- **Forgetting reduced-motion:** Wrap every `transition` prop with `getReducedMotionTransition(...)`. Phase 4 didn't ship reduced-motion handling on the side panel — this phase fixes that for new widgets only (panel is out of scope).

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Bubble packing (non-overlapping circles sized by value) | Custom physics solver / collision detection | `d3-hierarchy.pack()` | Solved problem; deterministic; ~10 LOC |
| Treemap rectangles | Manual recursion / golden-ratio split | `d3-hierarchy.treemap().tile(treemapSquarify)` | Squarified treemap is non-trivial; d3 has been this since 2010 |
| Calendar week/day grid | Manual `for` loops over `new Date()` | `d3-time.timeDays(start, end)` + `d3-time.timeWeek` | Timezone, DST, and ISO-week edge cases bite hard |
| Color interpolation for rarity intensity | `lerp()` between hex strings | `d3-scale.scaleSequential(d3-interpolate.interpolateBlues)` or `scaleLinear<string>().interpolate(interpolateRgb)` | Perceptually-uniform color space matters; manual hex lerp produces muddy mids |
| Spring physics for diff animation | `requestAnimationFrame` loop | `framer-motion` `motion.*` + `layoutId` + `<AnimatePresence>` | Already a dep; cancellation, interrupt handling, prefers-reduced-motion built in |
| Reduced-motion detection | Read `window.matchMedia` ad-hoc | `framer-motion`'s `useReducedMotion()` hook | Returns null on SSR safely; reactive to OS-level changes |
| Constellation orbit math | `Math.sin/cos` in render | Pre-compute `(cx, cy)` per node in `useMemo` once, animate with framer-motion's spring on the orbit phase | Keeps the 60fps target — no JS in the per-frame path |
| Skeleton placeholder | Use shadcn `<Skeleton>` rectangles | Hand-shaped per-widget skeletons (ghost circles, ghost grid) — already in `radix-ui` if needed | CONTEXT.md decision: skeletons must match final shape |

**Key insight:** d3-hierarchy + framer-motion is the modern React-d3 idiom — d3 owns the math, React owns the DOM, framer-motion owns the animation. Trying to merge them or replace one is the standard rookie mistake.

## Common Pitfalls

### Pitfall 1: `layoutId` collisions across widgets
**What goes wrong:** Two widgets both use `layoutId="role:foo"` — when one mounts and the other unmounts (e.g., during drag-reorder), framer-motion animates between them across the page.
**Why:** `layoutId` is a *global* shared-element id in framer-motion.
**How to avoid:** Always namespace: `layoutId={`recommendations:${kind}:${id}`}`.
**Warning signs:** A bubble flies across the screen during widget reorder.

### Pitfall 2: SortableWidget drag listener swallows widget keyboard events
**What goes wrong:** dnd-kit's `SortableWidget` attaches keyboard listeners (Space/Enter to lift). User pressing Enter on a bubble triggers a drag instead of a selection.
**Why:** dnd-kit listeners are attached at the card root.
**How to avoid:** Attach drag handle to a small "grip" affordance only (already the Phase 4 pattern — verify), and call `event.stopPropagation()` on the widget body's `onKeyDown`.
**Warning signs:** Widgets pick up and start dragging when the user presses Enter on an interactive element.

### Pitfall 3: framer-motion `layout` + SVG performance
**What goes wrong:** Using `motion.circle layout` (the `layout` prop) on SVG triggers expensive layout-projection calculations. For large element counts the FPS drops below 60.
**Why:** The `layout` prop is designed for HTML flow layout; on SVG attributes, animating `cx`/`cy`/`r` directly via `animate={{ cx, cy, r }}` is faster.
**How to avoid:** Animate attributes explicitly, not via `layout`. Use `layoutId` only for cross-widget shared-element transitions if needed.
**Warning signs:** DevTools paint flame chart shows >16ms in framer-motion's `measureLayout` during refresh.

### Pitfall 4: Refresh-diff selection lost
**What goes wrong:** After data refresh, the previously-selected role no longer exists; side panel either crashes or stays open with stale data.
**Why:** `selected` is a snapshot of the old finding object.
**How to avoid:** In `DashboardClient` (or in `SelectionProvider`'s value), reconcile `selected` against the new findings list when data changes — keep panel open with refreshed counts if id matches, otherwise call `clear()`.
**Warning signs:** Side panel shows "0 members" after refresh, or React error about reading a property of `undefined`.

### Pitfall 5: Calendar heatmap timezone shift
**What goes wrong:** A user added at `2026-05-01T23:30:00-07:00` (Pacific) shows up on May 2 in UTC, splitting daily counts across two cells.
**Why:** ACC `addedOn` is normalized to ISO at the cache write boundary (per Phase 4 P02 decision) — currently UTC.
**How to avoid:** Bucket by local-date string in the user's browser timezone using `date-fns.format(d, "yyyy-MM-dd")`. Be explicit in the widget's tooltip about which day's count is shown.
**Warning signs:** Off-by-one days versus the table the widget replaces.

### Pitfall 6: Constellation collision at low admin counts
**What goes wrong:** With 1 admin, the orbit is a single dot near the center. With 2 admins, they sit on opposite poles and look static.
**Why:** Orbit math degenerates at low N.
**How to avoid:** Empty/low-count fallbacks: 0 admins → empty-state message; 1 admin → centered single node with subtle pulse; 2 admins → enforce a minimum visual separation. CONTEXT.md `Deferred Ideas` says "handle inline during planning" — that's this row.
**Warning signs:** Visual emptiness or the constellation looking "broken" on small data.

### Pitfall 7: Treemap labels overflowing tiny cells
**What goes wrong:** Long module names render as `Document Management Manager` inside a 14×8 px outlier cell.
**Why:** d3-hierarchy returns rect dimensions; SVG `<text>` does not auto-clip.
**How to avoid:** Compute whether label fits (`node.x1 - node.x0 > MIN_LABEL_W && node.y1 - node.y0 > MIN_LABEL_H`); if not, omit label and rely on tooltip.
**Warning signs:** Text bleeding out of treemap cells.

### Pitfall 8: SVG `tabIndex` flaky in Safari
**What goes wrong:** `tabIndex={0}` on `<circle>` is unreliable across browsers.
**Why:** SVG focus support is uneven historically.
**How to avoid:** Wrap each interactive shape in a `<g role="button" tabIndex={0} ...>` (group element) — focus on the group is well-supported. Or use a transparent `<rect>` overlay per cell as a hit target.
**Warning signs:** Tab order skips bubbles in Safari.

### Pitfall 9: `useFindings()` recomputes during refresh
**What goes wrong:** During refresh, `findings` returns sentinel empty arrays (Phase 4 P07 pattern), causing `<AnimatePresence>` to exit-animate everything, then re-enter when data lands → 1.5s of animation noise on every refresh.
**Why:** Default behavior of `<AnimatePresence>` is element-by-element exit/enter.
**How to avoid:** Skip the empty-sentinel render: if findings are loading, show the skeleton (don't even render the SVG) so framer-motion never sees an exit phase. Or guard `<AnimatePresence>` with `mode="popLayout"` and a `key` on the parent fragment based on data identity.
**Warning signs:** Every refresh causes a full fade-out / fade-in instead of a smooth diff.

### Pitfall 10: Existing `SelectedFinding` union is not extensible without ripple
**What goes wrong:** Adding `kind: "admin"` and `kind: "day"` to the discriminated union forces `DashboardSidePanel.tsx`'s switch statement to handle the new kinds — TypeScript will catch this, but planner must include the panel update in the same wave that ships the widget.
**Why:** Discriminated-union exhaustiveness.
**How to avoid:** Wave 0 lands union extensions + panel switch updates BEFORE the widget rewrites in Wave 1.
**Warning signs:** `tsc --noEmit` errors in `DashboardSidePanel.tsx` after a widget plan is implemented in isolation.

### Treemap of module-set outliers
```tsx
// app/(dashboard)/users/dashboard/widgets/OutlierCombosWidget.tsx
"use client";
import { useMemo } from "react";
import { hierarchy, treemap, treemapSquarify } from "d3-hierarchy";
import { scaleSequential } from "d3-scale";
import { interpolateOranges } from "d3-scale-chromatic";
import { motion, AnimatePresence } from "framer-motion";
import { useFindings } from "../findingsContext";
import { useSelection } from "../selectionContext";
import { CELL_SPRING } from "./_shared/dashboardTokens";

const W = 360, H = 360;

export function OutlierCombosWidget() {
  const { outliers } = useFindings();
  const { setSelected } = useSelection();

  const layout = useMemo(() => {
    const root = hierarchy({ children: outliers.map((o) => ({ ...o, value: o.affectedMembers.length })) })
      .sum((d: any) => d.value ?? 0);
    return treemap().size([W, H]).tile(treemapSquarify).padding(2)(root).leaves();
  }, [outliers]);

  const rarity = scaleSequential(interpolateOranges).domain([0.05, 0]); // <5% threshold from DASH-03

  return (
    <svg viewBox={`0 0 ${W} ${H}`} role="img" aria-roledescription="module-set treemap">
      <AnimatePresence>
        {layout.map((node: any) => {
          const w = node.x1 - node.x0;
          const h = node.y1 - node.y0;
          return (
            <motion.g
              key={node.data.id}
              initial={{ opacity: 0 }}
              animate={{ opacity: 1, x: node.x0, y: node.y0 }}
              exit={{ opacity: 0 }}
              transition={CELL_SPRING}
              tabIndex={0}
              role="button"
              onClick={() => setSelected({ kind: "outlier", finding: node.data })}
              aria-label={`Module set ${node.data.modules.join(", ")}, ${node.data.affectedMembers.length} members`}
            >
              <motion.rect width={w} height={h} fill={rarity(node.data.share)} rx={2} />
              {w > 60 && h > 24 ? <text x={6} y={16} fontSize={11}>{node.data.modules[0]}</text> : null}
            </motion.g>
          );
        })}
      </AnimatePresence>
    </svg>
  );
}
// Source: d3-hierarchy treemap — https://d3js.org/d3-hierarchy/treemap
```

### Calendar heatmap (90-day GitHub-style)
```tsx
// app/(dashboard)/users/dashboard/widgets/RecentlyAddedWidget.tsx (excerpt)
"use client";
import { useMemo } from "react";
import { timeDays, timeWeek } from "d3-time";
import { scaleSequential } from "d3-scale";
import { interpolateBlues } from "d3-scale-chromatic";
import { format, subDays, startOfDay } from "date-fns";
import { motion } from "framer-motion";

const CELL = 14, GAP = 2;

export function RecentlyAddedWidget({ users }) {
  const today = startOfDay(new Date());
  const start = subDays(today, 89);
  const days = useMemo(() => timeDays(start, today), [start, today]);
  const counts = useMemo(() => {
    const m = new Map<string, number>();
    for (const u of users) {
      if (!u.addedOn) continue;
      const k = format(new Date(u.addedOn), "yyyy-MM-dd");
      m.set(k, (m.get(k) ?? 0) + 1);
    }
    return m;
  }, [users]);
  const max = Math.max(1, ...counts.values());
  const color = scaleSequential(interpolateBlues).domain([0, max]);

  return (
    <svg viewBox={`0 0 ${13 * (CELL + GAP)} ${7 * (CELL + GAP)}`}>
      {days.map((d) => {
        const k = format(d, "yyyy-MM-dd");
        const wk = Math.floor((d.getTime() - start.getTime()) / (7 * 86400_000));
        const dow = (d.getDay() + 6) % 7; // ISO Monday-first
        return (
          <motion.rect
            key={k}
            x={wk * (CELL + GAP)}
            y={dow * (CELL + GAP)}
            width={CELL}
            height={CELL}
            rx={2}
            fill={counts.get(k) ? color(counts.get(k)!) : "var(--secondary)"}
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            transition={{ delay: wk * 0.005 }}
          />
        );
      })}
    </svg>
  );
}
// Source: d3-time — https://d3js.org/d3-time
```
