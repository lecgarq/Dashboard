# Phase 04.1: Access Analysis tab — replace lists with astonishing, interactive graphics - Context

**Gathered:** 2026-05-08
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the four name-list / table widgets in the Access Analysis dashboard (`app/(dashboard)/users/dashboard/`) with interactive graphical visualizations. After this phase, the canvas itself shows zero name lists; member identities live exclusively in the existing `DashboardSidePanel` drill-down (or in CSV exports). The five already-graphical widgets may receive a polish pass for consistency with the new visual language, but no new dashboard capability is added. Auth, data fetching, widget-registry contract, and drag-order persistence from Phase 4 are unchanged.

Widgets in scope for replacement:
- `RecommendationsWidget` (junk + duplicate role table) → **Severity bubble cluster**
- `OutlierCombosWidget` (rare module-set table) → **Treemap of module-sets**
- `RecentlyAddedWidget` (joins-in-window table) → **Calendar heatmap**
- `AdminAccessWidget` (account admin table) → **Avatar / initial constellation**

Widgets eligible for in-scope polish (not redesign of capability):
- `CoverageDonutWidget`, `ActiveUserTiersWidget`, `KpiStripWidget`, `RolesModulesHeatmapWidget`, `RoleRelationshipFlowWidget`

</domain>

<decisions>
## Implementation Decisions

### Visualization mapping (1:1 replacements)
- **Recommendations → Severity bubble cluster.** Each finding = a bubble; size encodes affected-member count, color encodes severity (HIGH / MEDIUM / LOW). Junk and Duplicate findings clustered into two grouped regions. Click → side panel.
- **OutlierCombos → Treemap.** Each cell = a module combination; area = member count, color intensity = rarity. Outliers (low %) read as small cells. Click → side panel listing affected members.
- **RecentlyAdded → Calendar heatmap.** GitHub-style 90-day grid; color = joins per day. Window selector (7d / 30d / 90d) zooms/highlights the active band. Hover cell = aggregate count tooltip; click cell → side panel with that day's members.
- **AdminAccess → Avatar/initial constellation.** Each admin = an animated orbit node. Hover reveals initials only; click → side panel with name / role / email.

### Layout
- Keep current `widgetRegistry.ts` col-spans:
  - Bubble cluster (replaces Recommendations) → `col-span-2`
  - Treemap → `col-span-1`
  - Calendar heatmap → `col-span-1`
  - Constellation → `col-span-1`
- Existing five graphical widgets keep their spans.
- `DEFAULT_ORDER` array stays; widget IDs (`recommendations`, `outliers`, `recent`, `admins`) are reused so localStorage drag-order persists across the upgrade.

### Existing graphical widgets
- Open to redesign for consistency with the new visual language. Planner / researcher decides per widget whether a polish pass is needed (motion timing, palette tokens, hover treatment) — no functional changes, no scope expansion.

### CSV export
- Keep CSV download buttons on all four replacement widgets. Names exit the canvas but stay exportable.

### Aesthetic & motion
- **Direction:** Cosmos-gl matched. Pull palette + motion tokens directly from the existing graph tab so the dashboard feels like the same product.
- **Motion philosophy:** Physics-driven settle on entrance and on data-refresh diff (spring easing, animate position/size changes, fade in/out new/removed elements).
- **Palette:** Single shared semantic palette (HIGH / MEDIUM / LOW + neutral + highlight tokens) consumed by every widget. Defined once, reused.
- **Theme:** Equal polish in dark and light mode. Cosmos-leaning palette translated to light tokens explicitly; verify both.
- **Performance:** 60fps on entrance animation + interaction at 500–1000 ACC users.

### Rendering technology
- SVG via d3 + framer-motion for all four new widgets (data sizes are well under 500 elements per widget). Cosmos.gl-style aesthetic is matched via tokens, not engine.

### Drill-down & names
- **Click → existing `DashboardSidePanel`** via `selectionContext` (already shipped Phase 4). No modal, no inline expand.
- **Hover = aggregate tooltip only.** Counts and labels only — no individual member names on hover.
- **Constellation exception:** hover an admin orbit node shows initials; full identity still on click.

### Interactivity
- **Cross-widget linking via `selectionContext`.** Selecting an element in one widget highlights related members/roles in the other widgets (e.g., HIGH-severity bubble click → those members glow in heatmap, flow, constellation).
- **Hover treatment:** Lift + glow on hovered element; non-hovered elements fade to ~40% opacity (spotlight effect). Same pattern across all four new widgets.
- **Refresh transitions:** Animate diffs on `Refresh` click — bubbles/cells move/resize via spring; new items fade in, removed items fade out.
- **Pan/zoom:** None. All four widgets fit their card bounds.

### Accessibility
- **Keyboard nav:** Tab moves focus widget-to-widget; arrow keys traverse interactive elements within a widget; Enter selects (drives side panel).
- **Screen reader:** Per-element `aria-label` (e.g., "HIGH severity, role X, 12 members") plus a per-widget `aria-roledescription` and a brief summary text node.
- **Focus ring:** Cosmos-matched glow ring (slightly stronger than hover glow), not browser default.
- **Reduced motion:** Disable entrance and refresh-diff animations when `prefers-reduced-motion: reduce`; keep hover and selection transitions (they're subtle and informational).

### Empty / loading states
- Animated skeleton matching each widget's final shape (ghost bubbles, ghost grid, ghost orbit). Replaces the current generic shadcn `Skeleton` blocks for these widgets only.

### State & persistence
- **Selection state:** in-memory via `selectionContext`. Not encoded in URL.
- **Refresh resilience:** When data refreshes, attempt to preserve selection — if the selected element still exists in the new data, keep the side panel open with updated counts; if it's gone, close the panel gracefully.
- **Drag order:** Keep existing localStorage persistence (`acc-dashboard-widget-order`). Reuse current widget IDs so user-customized orders survive the upgrade.

### Claude's Discretion
- Browser back-button behavior while side panel is open (close-then-leave vs leave-immediately).
- Exact spring constants, palette token values, and skeleton animation timing.
- Which (if any) of the five existing graphical widgets need a polish pass — decide based on consistency review against the new tokens.
- Implementation sub-decisions (d3 layout choice for treemap, force layout for bubbles, orbit math for constellation, calendar grid cell size, etc.).

</decisions>

<specifics>
## Specific Ideas

- "Astonishing" reads as: the dashboard should feel cohesive with the cosmos.gl graph tab — same dark glow palette, same physics-driven motion vocabulary. The two tabs should feel like one product.
- Side panel is the workhorse for member-level detail — every name-revealing interaction routes there.
- Aggregate-only tooltips on hover. Resist the urge to show member names on hover anywhere except the constellation initials.

</specifics>

<deferred>
## Deferred Ideas

- **Side panel UX upgrades** (search/filter, multi-select compare, copy emails, paging when 100+ members) — useful but its own phase.
- **URL deep-linking of selection** (`?sel=outliers:id`) — explicitly out of scope for 04.1.
- **Edge-case audit** (0 admins / 1 admin / 200 outlier combos / very long role names) — handle inline during planning, no separate phase.
- **Calendar window > 90d** with horizontal scroll — defer until product asks for it.

</deferred>
