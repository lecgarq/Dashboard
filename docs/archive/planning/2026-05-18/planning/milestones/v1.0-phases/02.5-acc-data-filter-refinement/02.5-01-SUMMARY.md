# Phase 02.5 Plan 01: ACC Data Backbone (companyRole + lastSignIn) Summary

One-liner: Extended AccUser, AccGraphInstanceNode, CachedUser, and SimNode with companyRole and lastSignIn fields extracted via alias pattern from the ACC HQ v1 user record, with a one-time diagnostic log to confirm raw field names on next sync.

## What Was Built

Data pipeline extension so every runtime `SimNode` carries `companyRole: string | null` and `lastSignIn: string | null`. No DB schema changes — fields ride in the existing `AccMemberCache.data` JSON blob.

### Field extraction

Both `fetchAllAccUsers` and `fetchAccUserByEmail` in `lib/server/acc-admin.ts` now populate:

- `companyRole` via `u.company_role || u.companyRole` (same alias pattern as `company`)
- `lastSignIn` via `u.last_sign_in || u.last_activity || u.lastSignIn` (three-way alias covering documented and conventional field names)

### Diagnostic log

A one-time `console.info("[02.5-DATA-01] sample ACC raw user keys:", ...)` fires inside `fetchAllAccUsers` on the first user record of the first invocation per process. Gated by `let loggedRawShape = false` at module scope. Both log line and gate are marked `// TODO[02.5]: remove after first sync confirms field names` for easy cleanup.

**Field names not yet verified live** — per RESEARCH.md Pitfalls 1 and 2, `company_role` and `last_sign_in` are best-guesses from API conventions. The diagnostic log will reveal actual field names on the next deploy + sync.

### Type chain

```
AccUser (acc-admin.ts)
  └─ companyRole?: string
  └─ lastSignIn?: string
       ↓ written into AccMemberCache.data JSON blob (no migration)
CachedUser (graphSnapshot.ts)
  └─ companyRole?: unknown
  └─ lastSignIn?: unknown
       ↓ normalised in buildAccGraphSnapshot
AccGraphInstanceNode (graphSnapshot.ts)
  └─ companyRole: string | null
  └─ lastSignIn: string | null
       ↓ copied straight through in graphNodeToSimNode
SimNode / UserNode (AccUsersGraph.tsx)
  └─ companyRole: string | null
  └─ lastSignIn: string | null
```
