# Implementation Plan: Native LOD Checker Integration

> Generated by Antigravity on 2026-04-15
> Goal: Eliminate the iframe, kill the Flask server, migrate data to PostgreSQL/pgvector, and build a native Next.js LOD Checker module inside the Dashboard.

---

## Overview

### Current State
- LOD Checker is a **standalone Flask + Vite app** with its own auth, its own APS integration, and **831 MB of JSON files** loaded into Python memory
- Dashboard embeds it via **iframe** pointing to `localhost:5173` (80 lines, no real integration)
- Two separate OAuth flows, two separate processes, not deployable

### Target State
- LOD Checker is a **native Dashboard module** — same auth, same database, same deployment
- Data stored in **PostgreSQL + pgvector** (Supabase) — eliminates 831 MB JSON
- Search via **pgvector cosine similarity** + tRPC — eliminates Flask/numpy
- Graph visualization as **native React components** — eliminates Vite SPA
- ML pipeline remains a **local CLI tool** that uploads results to the database via API

## Phase 2: Data Migration Script

### Script: `scripts/migrate-lod-data.ts`

A one-time Node.js script that:

1. Reads `master_registry.json` (streaming JSON parser to avoid OOM)
2. Reads `graph_data.json`
3. Reads `Categories.json`
4. For each record:
   - Creates `LodFamily` row
   - Creates `LodEmbedding` row with float array
   - Creates `LodGraphNode` row with x/y/neighbors
5. Updates pgvector column via raw SQL: `UPDATE "LodEmbedding" SET pgvector = vector FROM (SELECT ...) ...`
6. Creates `LodCategory` rows

### Image Migration

Two options:

**Option A: UploadThing** — Upload all thumbnails to UploadThing CDN, store URLs in `imagePath`/`thumbPath`. Pros: CDN-backed, works on Railway. Cons: Slow initial upload (thousands of files).

**Option B: Static serving** — Copy images to `public/lod-images/` in the Dashboard repo. Pros: Simple. Cons: Bloats repo. Not recommended for production.

**Recommended: Option A** (UploadThing) with a batch migration script.

### Search Implementation (pgvector)

```typescript
async function lodSearch(query: string, ctx: Context) {
  // 1. OpenAI text embedding (768-dim, same model as SigLIP)
  const queryEmbedding = await computeTextEmbedding(query);

  // 2. pgvector similarity search
  const results = await ctx.db.$queryRaw`
    SELECT f.*, e."pgvector" <=> ${queryEmbedding}::vector AS distance
    FROM "LodEmbedding" e
    JOIN "LodFamily" f ON f.id = e."familyId"
    ORDER BY e."pgvector" <=> ${queryEmbedding}::vector
    LIMIT 200
  `;

  return results;
}
```

```typescript
import pLimit from "p-limit";

const limit = pLimit(3); // MaxDegreeOfParallelism = 3

const results = new Map<string, ApsSearchResult>();
const topFolders = await getCachedTopFolders(hubId, projectId, token);

await Promise.allSettled(
  topFolders.map(folder =>
    limit(async () => {
      const controller = new AbortController();
      const timeout = setTimeout(() => controller.abort(), 60_000); // 60s per folder
      try {
        await searchFolderPass(projectId, folder, token, results, controller.signal);
      } catch (err) {
        if (err instanceof DOMException && err.name === "AbortError") {
          logger.warn(`APS search timed out for folder: ${folder.name}`);
        }
      } finally {
        clearTimeout(timeout);
      }
    })
  )
);
```

#### Full Folder Path Resolution (Port of `EnsureFolderChainAsync`)

```typescript
const folderCache = new Map<string, { name: string; parentId: string }>();

async function ensureFolderChain(
  projectId: string, startId: string, rootId: string,
  rootName: string, token: string
): Promise<void> {
  let current = startId;
  for (let depth = 0; depth < 25 && current && current !== rootId; depth++) {
    if (folderCache.has(current)) {
      current = folderCache.get(current)!.parentId;
      continue;
    }
    // Fetch folder metadata from APS
    const res = await fetch(
      `https://developer.api.autodesk.com/data/v1/projects/${projectId}/folders/${encodeURIComponent(current)}`,
      { headers: { Authorization: `Bearer ${token}` } }
    );
    if (!res.ok) break;
    const data = await res.json();
    const name = data.data?.attributes?.name ?? "";
    const parentId = data.data?.relationships?.parent?.data?.id ?? "";
    if (!name) break;
    folderCache.set(current, { name, parentId });
    current = parentId;
  }
}

function resolveFolderPath(startId: string, rootId: string, rootName: string): string {
  const parts: string[] = [];
  let current = startId;
  for (let depth = 0; depth < 25 && current; depth++) {
    if (current === rootId) { parts.push(rootName); break; }
    const info = folderCache.get(current);
    if (!info) break;
    parts.push(info.name);
    current = info.parentId;
  }
  return parts.reverse().join(" / ") || rootName;
}
```

### `LodGraphCanvas` — The Hard Part

This is the most complex component to port. It renders thousands of nodes on a `<canvas>` element with:

- UMAP-projected 2D positions
- KNN-based neighbor edges
- Dynamic layout modes (similarity, category, LOD, provider)
- Zoom/pan interactions
- Node selection with detail panel
- Search result highlighting (glow on matched nodes)
- Animated transitions between layouts

**Strategy**: Port the canvas rendering logic as-is (it's framework-agnostic), wrap it in a React component with `useRef` + `useEffect` for lifecycle management.
