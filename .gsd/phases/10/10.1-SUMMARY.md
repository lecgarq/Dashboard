# Summary: UploadThing Orphan Cleanup on Task Delete

## What was built

Updated `server/routers/tasks.ts` so `deleteTask` captures attachment URLs before deleting the task row, derives UploadThing file keys from the `/f/` segment, and then calls `utapi.deleteFiles(fileKeys)` after the database delete completes.

The UploadThing cleanup is wrapped in a `try/catch` and logs through the server logger. That keeps Prisma deletion authoritative: a storage cleanup failure does not roll back the task delete mutation.

## Files modified

- `server/routers/tasks.ts`

## Outcome

Task deletion now attempts to remove linked UploadThing assets in tandem with the row cascade, reducing orphaned object storage growth while preserving the existing mutation return behavior.
