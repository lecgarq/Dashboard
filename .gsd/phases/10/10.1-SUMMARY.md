# Summary: ACC Graph Topology & Canvas Expansion

## What was built

Phase 10.1 added ACC graph hub topology for Projects, Roles, and Modules so user instances are no longer rendered as disconnected points. The snapshot builder now emits hub nodes plus typed edges from each user instance to its project, role, and module hubs, and the graph UI renders those hubs as first-class nodes with their own labels, tooltips, and side-panel content.

The canvas layout logic was also corrected to preserve a 1:1 coordinate space. Both the snapshot normalization and the client-side normalization use a single max range for X/Y so the graph no longer stretches vertically on resize. Spacing controls and semantic weighting keep clusters broad while still preserving project, role, access, and module grouping.

Force tuning in the shared simulation widened inter-cluster separation and reduced hub drift so the graph reads as distinct, airy groups rather than a dense central knot.

During verification, the ACC graph cache rebuild path was also corrected so hub snapshot nodes translate to concrete simulation kinds (`project`, `role`, `module`) before running shared physics. That keeps the server-side cache rebuild aligned with the new hub-node schema.

## Outcome

ACC users now render around explicit project, role, and module hubs with cleaner topology, square normalization, and broader spacing. Phase 10.1 remains graph-focused work; no dashboard API contract changed as part of this package.

Deployment note: the Yjs collaboration server is a separate Railway service and should build from `Dockerfile.yjs` through `railway.yjs.toml`, not from the dashboard root `Dockerfile`.
