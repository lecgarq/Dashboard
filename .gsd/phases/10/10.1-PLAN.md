# Plan 10.1: ACC Graph Topology & Canvas Expansion

## Objective
The current ACC graph feels vertically squashed and lacks clear clustering because it only represents users as floating instances without their central connections (Projects, Roles, Modules). This plan will introduce "Hub nodes" to the physical simulation to anchor clusters, fix the aspect ratio calculation, and broaden node separation.

## Context
- `lib/acc/graphSnapshot.ts` (Topology generation)
- `app/(dashboard)/users/AccUsersGraph.tsx` (Rendering & Normalization)
- `lib/acc/graphSimulation.ts` (Force parameters)

## Success Criteria
- [ ] Projects, Roles, and Modules appear as central Hub nodes.
- [ ] Clusters of users are visibly pulled towards their respective hubs.
- [ ] Vertical stretching is completely eliminated.
- [ ] The graph feels "broad" and "airy" rather than "compact" and "joined".

## Package Scope Note
- Phase 10.1 is ACC graph topology, rendering, and physics work only.
- The wiki collaboration Yjs server is a separate deployable service and is not part of the dashboard Next.js build output.

## Deployment Verification Addendum
- Dashboard app build: `npm run build`
- Yjs service build: build from `Dockerfile.yjs` via `railway.yjs.toml`; this path must not run `npm run build`
- Yjs service runtime: start `node scripts/yjs-server.mjs` with `DATABASE_URL`, `AUTH_SECRET` or `NEXTAUTH_SECRET`, and `PORT`
- Client wiring: `NEXT_PUBLIC_YJS_WS_URL` remains the explicit override, with the documented Railway fallback when unset
