## 7. Type Safety Violations

### `as any` Casts (Server-Side)

| File | Line | Cast | Risk |
| --- | --- | --- | --- |
| `server/trpc.ts` | 46 | `(ctx.session.user as any).role` | Role access is untyped at the procedure level |
| `server/trpc.ts` | 52 | `(ctx.session.user as any).role` | Same issue — role should be in proper type |
| `server/auth.ts` | 121 | `} as any` | Credentials authorize return — should be properly typed |
| `server/auth.ts` | 129 | `PrismaAdapter(db) as any` | Known NextAuth v5 beta adapter type mismatch |
| `server/auth.ts` | 187 | `account as any` | Used to access `access_token` etc. — should use proper Account type |
| `server/auth.ts` | 264-267 | 4× `as any` casts | Session user augmentation — `next-auth.d.ts` types exist but aren't flowing through |

**Root Cause**: The `next-auth.d.ts` type declarations exist but aren't fully connected to the auth callbacks. The session `user` type doesn't include `role`, `providers`, `hasCredentials`, `moduleAccess` in the callback signatures.

**Fix**: Properly extend `AdapterUser` and `Session["user"]` so the callbacks receive typed objects.

## 8. Database Query Optimization

### Missing Indexes

| Model | Column | Query Location | Impact |
| --- | --- | --- | --- |
| `Family` | `phase` | `kpi.ts` (5 queries) | Full table scan on every dashboard load |
| `Family` | `dueDate` | `kpi.ts` (deadline queries) | Sequential scan for future dates |
| `Family` | `updatedAt` | `kpi.ts` (recent families) | Sort without index |
| `ClashTask` | `status` | `kpi.ts` (3 queries) | Full table scan |
| `ClashTask` | `dueDate` | `kpi.ts` (deadline queries) | Sequential scan |
| `SimTask` | `status` | `kpi.ts` (via sim router) | Full table scan |
| `User` | `username` | `auth.ts` (login by username) | Scan on non-unique field |

### Fix: Add to `schema.prisma`

```prisma
model Family {
  @@index([phase])
  @@index([dueDate])
  @@index([updatedAt])
}

model ClashTask {
  @@index([status])
  @@index([dueDate])
  @@index([updatedAt])
}

model SimTask {
  @@index([status])
  @@index([dueDate])
}

model User {
  @@index([username])
}
```

### 17-Query KPI Blast

`kpi.getHomeDashboard` fires **17 parallel Prisma queries** on EVERY homepage load. Even though they run in parallel, this creates a burst of 17 connection checkouts from the Supabase pool.

**Impact**: Under concurrent load, this can exhaust the 15-connection Supabase pool limit.

**Fix**: Consolidate into 2-3 raw SQL CTEs:

```sql
WITH counts AS (
  SELECT
    (SELECT COUNT(*) FROM "Family") AS family_total,
    (SELECT COUNT(*) FROM "Family" WHERE phase = 'DONE') AS family_done,
    (SELECT COUNT(*) FROM "ClashTask") AS clash_total,
    (SELECT COUNT(*) FROM "ClashTask" WHERE status = 'DONE') AS clash_done,
    (SELECT COUNT(*) FROM "User") AS user_count
)
SELECT * FROM counts;
```

### Raw SQL Bypassing Prisma

| File | Line | Query | Risk |
| --- | --- | --- | --- |
| `auth.ts` | 171 | `$executeRaw UPDATE "User"` | Bypasses Prisma hooks and default values |
| `auth.ts` | 180 | `$executeRaw INSERT INTO "User"` | Manual insert — no validation |
| `auth.ts` | 252 | `$queryRaw SELECT module FROM "UserModuleAccess"` | Should use `db.userModuleAccess.findMany()` |

## 11. Railway Deployment Reliability

### Current Gaps

| Gap | Risk | Fix |
| --- | --- | --- |
| **No health check endpoint** | Railway can't verify app is serving | Add `GET /api/health` |
| **No `railway.toml`** | Relies on Nixpacks auto-detection | Add explicit build/deploy config |
| **No `postinstall` script** | `prisma generate` may not run | Add `"postinstall": "prisma generate"` |
| **No engine lock** | Node version drift | Add `"engines": { "node": ">=20" }` |
| **`@ngrok/ngrok` in prod deps** | Bloats Railway build by ~15MB | Move to `devDependencies` |
| **No build caching** | Every deploy reinstalls from scratch | Configure Railway deploy cache |
| **Double env vars** | `AUTH_SECRET`/`NEXTAUTH_SECRET` duplication | Remove `NEXTAUTH_SECRET` and `NEXTAUTH_URL` |

### Recommended `railway.toml`

```toml
[build]
builder = "nixpacks"
buildCommand = "npx prisma generate && npm run build"

[deploy]
startCommand = "npm start"
healthcheckPath = "/api/health"
healthcheckTimeout = 30
restartPolicyType = "on_failure"
restartPolicyMaxRetries = 3
```

### Recommended Health Check

```typescript
// app/api/health/route.ts
export function GET() {
  return Response.json({
    status: "ok",

    node: process.version,
  });
}
```

### Recommended `package.json` Additions
