## 📊 Database Query Optimization

### Unindexed Queries

The following queries use `WHERE` clauses on columns that likely lack indexes:

| Router | Query | Missing Index |
| --- | --- | --- |
| `kpi.ts` | `family.count({ where: { phase: "DONE" } })` | `Family.phase` |
| `kpi.ts` | `clashTask.count({ where: { status: "DONE" } })` | `ClashTask.status` |
| `kpi.ts` | `family.findMany({ where: { dueDate: { gt: now } } })` | `Family.dueDate` |
| `kpi.ts` | `clashTask.findMany({ where: { dueDate: { gt: now } } })` | `ClashTask.dueDate` |
| `search.ts` | `family.findMany({ where: { name: { contains: term } } })` | `Family.name` (consider `pg_trgm` for full-text) |
| `users.ts` | `user.findFirst({ where: { OR: [{ email }, { username }] } })` | `User.username` (email is already unique) |
| `sheets.ts` | `approvedEmail.findUnique({ where: { email } })` | OK (unique index exists) |

### Recommended Prisma Schema Addition

```prisma
model Family {
  // ...
  @@index([phase])
  @@index([dueDate])
}

model ClashTask {
  // ...
  @@index([status])
  @@index([dueDate])
}
```

### 17-Query KPI Blast

`kpi.getHomeDashboard` fires **17 parallel database queries** on every homepage load. While `Promise.all` prevents waterfall, this creates a burst of 17 connections from the Supabase pool.

**Recommended Fix**: Consolidate into 2-3 raw SQL queries using `$queryRaw` with CTEs:

```sql
WITH family_counts AS (
  SELECT
    COUNT(*) AS total,
    COUNT(*) FILTER (WHERE phase = 'DONE') AS done,
    COUNT(*) FILTER (WHERE phase IN ('REVIEW', 'DONE')) AS review
  FROM "Family"
),
clash_counts AS (
  SELECT
    COUNT(*) AS total,
    COUNT(*) FILTER (WHERE status = 'DONE') AS done
  FROM "ClashTask"
)
SELECT * FROM family_counts, clash_counts;
```

### Raw SQL in Auth

`server/auth.ts` uses 3 raw SQL calls (`$executeRaw`, `$queryRaw`) that bypass Prisma's type safety:

| Line | Query | Risk |
| --- | --- | --- |
| 171 | `UPDATE "User" SET role = ... WHERE id = ...` | Bypasses Prisma hooks, no type checking |
| 180 | `INSERT INTO "User" ...` | Manual insert bypasses default values |
| 252 | `SELECT module FROM "UserModuleAccess" WHERE "userId" = ...` | Should use `db.userModuleAccess.findMany()` |

**Recommended Fix**: Replace all `$executeRaw`/`$queryRaw` with Prisma client methods.

## 🚀 Railway Deployment Reliability

### Current Issues

| Issue | Impact | Fix |
| --- | --- | --- |
| **No `Dockerfile`** | Relies on Nixpacks auto-detection, which can misdetect build steps | Add a `Dockerfile` or `railway.toml` for deterministic builds |
| **No health check endpoint** | Railway can't verify the app is actually serving requests | Add `GET /api/health` that returns `{ status: "ok", timestamp }` |
| **No build cache optimization** | Every deploy reinstalls all dependencies from scratch | Add `railway.toml` with cache configuration |
| **`prisma generate` not explicit** | May fail silently if the Prisma client isn't generated pre-build | Add `"postinstall": "prisma generate"` to `package.json` |
| **No zero-downtime deploy** | Default Railway behavior may have brief downtime during swap | Configure Railway's rolling deploy settings |
| **Missing `DIRECT_URL` in migrations** | Supabase pooler (port 6543) doesn't support `prisma migrate` | Use `DIRECT_URL` (port 5432) for migrations only |

### Recommended `railway.toml`

```toml
[build]
builder = "nixpacks"
buildCommand = "npx prisma generate && npm run build"

[deploy]
startCommand = "npm start"
healthcheckPath = "/api/health"
healthcheckTimeout = 30
restartPolicyType = "on_failure"
restartPolicyMaxRetries = 3
```

### Recommended Health Check

```typescript
// app/api/health/route.ts
export function GET() {
  return Response.json({
    status: "ok",
    timestamp: new Date().toISOString(),
    node: process.version,
  });
}
```
