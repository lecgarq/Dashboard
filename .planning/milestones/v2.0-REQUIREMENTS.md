## In-Scope Requirements — all Complete ✓

Scoped to 4 pages — `/users`, `/access-analysis`, `/template-mty`, `/forma-proposal`. Foundation, Speed, Interactivity, and Visual items are cross-cutting (built once, applied to all 4); per-page items layer on top.

### Foundation & Design System

- [x] **FND-01** ✓ — Shared depth/glow/glass design-token set in `globals.css` drives all 4 pages (no hardcoded hex in TSX). *Outcome: validated.*
- [x] **FND-02** ✓ — Reusable `PremiumSurface` card primitive (base/float/glass/inset) replaces ad-hoc panel styling. *Outcome: validated.*
- [x] **FND-03** ✓ — Single shared `EChart` wrapper auto-applies light/dark theme via `resolvedTheme`. *Outcome: validated.*
- [x] **FND-04** ✓ — Central motion facade exposes reveal/stagger presets and disables motion under `prefers-reduced-motion`. *Outcome: validated (code-level; live media-query path carried forward as a manual check).*
- [x] **FND-05** ✓ — Reusable virtualized `DataTable` primitive (sort, sticky header, row-click, inline expand, density toggle). *Outcome: validated.*

### Speed & Perceived Performance

- [x] **PERF-01** ✓ — Each page shows a skeleton/loading state within ~200ms of navigation. *Outcome: validated.*
- [x] **PERF-02** ✓ — `/access-analysis` renders its first tier (KPIs + donuts) fast (~300ms target), streaming heavier tiers progressively. *Outcome: validated.*
- [x] **PERF-03** ✓ — Each tRPC endpoint fetched at most once per page load. *Outcome: validated — hydration-key double-fetch eliminated.*
- [x] **PERF-04** ✓ — `/users` initial client payload reduced (heavy per-user data deferred to detail-open); no load-time regression. *Outcome: validated.*
- [x] **PERF-05** ✓ — No page introduces a new WebGL context on a data surface (GPU < 400MB). *Outcome: validated.*

### Interactivity & Drill-down

- [x] **INT-01** ✓ — Single shared slide-in detail panel (shadcn `Sheet`) is the drill-target for every click source. *Outcome: validated.*
- [x] **INT-02** ✓ — Chart segments clickable, open relevant people/detail in the slide-in panel. *Outcome: validated.*
- [x] **INT-03** ✓ — Table rows clickable (open detail) and expandable inline (summary), no full-page navigation. *Outcome: validated.*
- [x] **INT-04** ✓ — On `/access-analysis`, clicking a chart cross-filters the other charts client-side (zero new queries). *Outcome: validated — the headline differentiator.*
- [x] **INT-05** ✓ — Active-filter/drill-state pill bar shows current filters with one-click dismiss. *Outcome: validated.*

### Visual Depth & Motion

- [x] **VIS-01** ✓ — Chart panels and key surfaces use 2.5D depth (glass, layered shadow, catch-light) in both themes. *Outcome: validated.*
- [x] **VIS-02** ✓ — Donut/pie charts use gradient fills, selected-segment glow, rounded segments. *Outcome: validated.*
- [x] **VIS-03** ✓ — Content reveals with a staggered entrance under a hard motion budget (< 400ms, once per load). *Outcome: validated.*
- [x] **VIS-04** ✓ — KPI numbers count up smoothly on first load. *Outcome: validated.*
- [x] **VIS-05** ✓ — Drill-down transitions smooth and directional (≤ 200ms); motion fires only on mount/drill, never on filter change. *Outcome: validated.*
- [x] **VIS-06** ✓ — One or two selective real-3D hero accents only on non-data regions (`/forma-proposal` background, `/users` header). *Outcome: validated.*

## Deferred to v-next (acknowledged, not in this milestone)

- **FRM-V2-01**: Role-permission diff view (requires a new `template.getBaseline(roleId)` tRPC query; HIGH complexity, fully independent).
- **ACC-V2-01**: Project-grouped persistent accordion in the project picker (current dropdown is functional).
- **NA-V2-01**: Additional new analytics beyond the gated per-page set.
- `/users` data freshness / auto-refresh (pre-existing app-wide caching; confirmed not a Phase 2 regression).

## Out of Scope (reasoning held through the milestone)

| Feature | Reason |
|---------|--------|
| `/users/spatial-graph` redesign | Separate future project; needs full dedicated attention (real 3D). Boundary held — zero files under `users/access-analysis/` touched. |
| New data pipelines / external integrations | Existing Prisma DB is the single source of truth |
| Data model / Prisma schema changes | Read-only query/index additions only; no model changes |
| End-user engagement / retention features | Presentation/workshop showcase, not an engagement product |
| `echarts-gl` or WebGL on data pages | GPU budget + speed constraint; depth comes from CSS/ECharts instead |
| Backend / data-architecture redesign | Server-driven hybrid stays; presentation-layer surgery only |
