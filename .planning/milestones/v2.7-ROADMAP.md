## ✅ v2.7 Activity Universe (Opened 2026-07-20 — Shipped 2026-07-22)

**Milestone goal:** Change the spatial graph's node grain from user×project instances
(22,279 nodes) to **one node per extracted activity event** — the full raw corpus
(4,862,301 `AccActivityAccds` rows + DC backfill/admin, measured 2026-07-20) — with every
node inheriting its author's properties (role, company, modules) plus its own event
properties (verb, module, objectType, folder, month). Full replace of the user-instance
graph (owner decision, dimension sliders preserved), temporal scrubber folded in (TIME-01),
and the v2.6 hard **≥50 fps Tier-0** bar applied at the shipped scale.

**Source requirements:** `.planning/REQUIREMENTS.md` (v2.7, 12 requirements: SCALE-01/02,
ACT-01–04, EMB-07, DIM-07, PERF-07, TIME-01, REND-04, E2E-03). **12/12 mapped, each to
exactly one phase.**

**Overarching guardrail:** this is a ~220× scale jump on every layer (renderer, embedding
pipeline, payload, morph path, e2e baselines — all currently sized for 22k). Phase 37's
feasibility spike picks the shipped rung on the owner-approved fallback ladder
(L0 all-animated → L1 decimated ambient → L2 far-zoom LOD → L3 verb+month grain 106,196)
BEFORE any build phase; the hard gate is measured last at that rung. A failed rung produces
a recorded owner decision, not a dead milestone (v2.5 LIFE-03 clause discipline). New
Prisma table + raw-SQL migration expected (pgvector shadow-DB trap: never `migrate dev`).
The 23-panel `/access-analysis` charts page and `/template-mty` are untouched;
TEST-01/02/03 stay green.

## Phase Details

### Phase 37: Scale Feasibility Spike & Fallback Ladder

**Goal**: The milestone's biggest unknown — can the workshop machine hold 4,862,301 GPU
points — is answered with measured numbers before any build phase, and the shipped ladder
rung is an owner-approved recorded decision, not an assumption.
**Depends on**: Phase 36 (v2.6, shipped) — first phase of v2.7.
**Requirements**: SCALE-01
**Success Criteria** (what must be TRUE):

  1. A cosmos.gl prototype renders the full 4,862,301-point set (synthetic or real
     positions) on the workshop machine; fps at rest / during pan+zoom / with ambient
     motion, GPU memory, and context-loss behavior are measured and recorded in
     `37-BASELINE.md` (SCALE-01).
  2. A binary payload prototype (typed-array positions + minimal attribute columns) is
     measured: bytes on the wire, load + parse + upload time; the numbers ground the
     SCALE-02 time-to-graph budget (SCALE-01).
  3. The offline embedding runtime at activity grain is estimated from a measured
     sample-fit (full-fit PaCMAP vs sample-fit + kNN projection), recorded (SCALE-01).
  4. The fallback ladder rung to ship (L0 all animated → L1 decimated ambient → L2
     far-zoom LOD → L3 verb+month grain 106,196) is chosen from the recorded evidence with
     explicit owner sign-off captured in the phase artifacts; every later phase builds to
     that rung (SCALE-01).
  5. No production surface changes in this phase — spike code is isolated (route flag or
     scratch harness); `npx tsc --noEmit` stays clean if any repo file is touched.

**UI hint**: no (spike; owner sees numbers + a live demo of the prototype, not a shipped
surface).

### Phase 38: Activity Data Pipeline & Embedding

**Goal**: Every activity event has a computed 2D position and enriched author + event
attributes stored at activity grain, and the client can load the full set as binary
columnar payloads inside the measured budget.
**Depends on**: Phase 37 (ladder rung + budgets fixed).
**Requirements**: SCALE-02, EMB-07, ACT-02
**Success Criteria** (what must be TRUE):

  1. An offline pipeline (python, pacmap+faiss-cpu lineage) computes deterministic 2D
     positions for the full corpus at the shipped rung — full-fit or sample-fit+projection
     per Phase 37 evidence, decision + runtimes recorded; deterministic seed proven twice;
     quality-gate regression aborts before any write (EMB-07).
  2. A new activity-grain Prisma table stores positions + the attribute columns the graph
     needs, applied via raw-SQL migration + `prisma migrate resolve`; ingest wiring is
     non-fatal (EMB-07).
  3. The feature vector includes author properties (role, company, modules) AND event
     properties (verb, module, objectType, folder, month) — the author's properties
     literally shape the layout (EMB-07).
  4. The null/unresolved-author rate is measured against the live corpus and recorded; the
     coverage figure flows to the graph surface as an honest label; unresolved nodes carry
     an explicit "Unknown author" grouping (ACT-02).
  5. A route serves binary columnar payloads (typed arrays, no per-node JSON); median-of-5
     `:3100` time-to-graph meets the Phase-37 budget, recorded (SCALE-02).

**UI hint**: no (server/pipeline phase; the graph still renders the old universe until
Phase 39).

### Phase 39: Activity Universe Swap

**Goal**: `/users/spatial-graph` renders the activity universe — every extracted activity
event at the shipped rung, colored/sized from real event data, with the user-instance
graph fully retired and node interaction telling each event's story.
**Depends on**: Phase 38 (positions + payload live).
**Requirements**: ACT-01, ACT-03, ACT-04
**Success Criteria** (what must be TRUE):

  1. The graph renders one node per activity event at the shipped rung with event
     properties resolved (verb, module via `activityClassification.ts`, objectType,
     folder, project, month), theme-resolved colors, organic layout (ACT-01).
  2. The user×project instance data path is fully retired — old per-instance payload,
     loaders, and dead code removed with a clean diff; no orphaned loader ships bytes;
     repo-map check green (ACT-03).
  3. Hover/click on a node shows the event (verb, object, folder, project, date, author)
     and the author's profile (reusing `UserProfilePanel` where it fits); selection/lasso
     works at the shipped scale (ACT-04).
  4. Reduced-motion renders fully static; empty/error states honest; zinc theme intact
     (standing guardrails).
  5. Gates: tsc, focused Vitest for new transforms, TEST-01/02/03 untouched-surface pins
     green, repo-map check.

**UI hint**: yes — this is the milestone's headline visual change; owner sees the live
universe before the phase closes.

### Phase 41: Time Scrubber, Hard Gate & Closeout

**Goal**: The temporal scrubber lands, the e2e suite can gate the new universe, the hard
≥50 fps Tier-0 gate passes at the shipped rung measured last, and the milestone deploys
and closes.
**Depends on**: Phase 40 (full feature surface in place — measure-last discipline).
**Requirements**: TIME-01, REND-04, E2E-03
**Success Criteria** (what must be TRUE):

  1. A temporal scrubber filters the graph by month across the corpus (GPU-mask or
     equivalent), can animate month-over-month, and stays inside the perf bar while
     scrubbing; `prefers-reduced-motion` → static stepping only, no auto-animation

  2. `acc-dc-graph.spec.ts` + lasso spec re-baselined to the activity universe (node
     counts, selectors, CI-sized `NEXT_PUBLIC_ACC_GRAPH_TEST` activity fixture) and green
     on the isolated `:3100` harness (E2E-03).

     LIFE-03-methodology sample on the workshop machine, tier controller observed idle,
     recorded in `41-VERIFICATION.md`; if shipping below L0, the Phase-37 owner sign-off
     is referenced (REND-04).
  4. Time-to-graph re-measured vs the Phase-38 budget — regression blocks the phase.
  5. Full gate sweep green (tsc, npm test, TEST-01/02/03, e2e, repo-map); deploy per
     autoDeploy policy with authenticated populated-graph probe recorded; milestone
     close follows via `/lecg-close-milestone`.
