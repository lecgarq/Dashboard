# Phase 2.5: ACC Data + Filter Refinement - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Filter UI hides non-matching nodes from the canvas (fully hidden, not greyed-out); ACC `companyRole` is extracted into the user record and surfaced as a filter dimension and side-panel field; date filter exposes inclusive `from`/`to` inputs; module filters render as on/off toggles where all-on shows everything and toggling off filters out users.

Requirements: DATA-01, FILT-01, FILT-02, FILT-03.

</domain>

<decisions>
## Implementation Decisions

### Hide behavior & cascading
- Edges to/from hidden user nodes are **fully hidden** (not dimmed). Matches spec wording.
- **Cascade hide is recursive**: when a Project/Role/Module node has zero visible connected users it auto-hides; if hiding a Project then orphans a Role with no other projects, the Role also hides; etc. Graph only shows what's relevant to the current filter.
- After filters change the visible node set, the **physics simulation reflows the layout** (visible nodes settle into a new arrangement based on remaining edges). This will re-trigger Phase 3's "Stable" badge once it settles.
- **Empty state**: when zero nodes match, show an overlay message ("No users match these filters — adjust filters to see results") with a "Clear filters" button.
- **Click-through on hidden node positions**: nothing happens. No hit-testing on hidden nodes.
- Filters **persist in URL query params** (e.g. `?modules=x,y&from=...&to=...`). Shareable, survives refresh, follows the existing nav-state pattern from Phase 1.
- **Drag-while-filter-changes**: defer the hide until the drag interaction ends, then apply.
- **Hide transition**: brief fade-out (~150ms). Animation is acceptable; keep it cheap on Cosmos.gl and Canvas2D.
- **Filter panel header** shows a count summary like `Showing 47 of 312 users` whenever any filter is active.
- **"Clear all filters" button** is visible in the filter panel only when at least one filter is non-default; one click resets everything to all-on / empty range.

### companyRole extraction & display
- Source: **ACC Admin API user record top-level field**. Extract during the existing ACC sync into the user table.
- **Null/missing values**: persist null in DB; display as `Unspecified` in the side panel and as an `Unspecified` bucket in the filter dropdown.
- **Filter UX**: multi-select dropdown of distinct values **with a search box at the top** for long lists.
- **Side-panel display**: plain row alongside other user fields (e.g. `Company Role: Architect`), consistent with existing panel layout. No special badge.

### Date filter semantics
- The "relevant date" field is **`lastActivity` / `lastSignIn`** on the user. (Use case: stale-user / recent-activity analysis.)
- **Users with no `lastActivity` value are excluded** when a date range is active. With no range set, they're visible.
- **Default state on load**: no range set (both inputs empty) → all users visible. User opts in to filtering.
- **Input style**: two native `<input type="date">` fields labeled `From` and `To`. No date-picker dependency.
- Range is **inclusive** on both ends (matches spec).

### Module toggle logic
- **Multi-module behavior**: a user with access to Modules A and B remains visible when A is toggled off and B is on. The user is filtered out only if **all** modules they have access to are toggled off (i.e. their access intersects only off modules). Matches spec wording literally.
- **Default state**: all module toggles ON → every user visible. User opts out per module to narrow down.
- **Toggle UI**: iOS-style switch toggles (one per module, vertical list).
- **Users with no module access**: always visible regardless of module toggles. Other filters (date, companyRole) still apply to them.

### Claude's Discretion
- Exact location/styling of the empty-state overlay
- Exact placement and styling of the "Clear all filters" button
- Animation tween curve for the 150ms fade-out
- Sync cadence for companyRole (assumed to ride existing ACC sync)
- DB column type and migration shape for `companyRole`
- Search-box implementation details for the companyRole multi-select dropdown
- Renderer-specific implementation of hide (Canvas2D vs Cosmos.gl)

</decisions>

<specifics>
## Specific Ideas

- "Fully hidden, not greyed-out" is a hard constraint (came from the roadmap and reinforced in discussion).
- Recursive cascade is explicit user intent — Project/Role/Module nodes should disappear when they have nothing to connect to under the current filter.
- URL-param persistence aligns with the existing nav-state pattern established in Phase 1 (navigation state persistence + loading timeout).
- Date filter targets `lastActivity` specifically because the user wants to surface stale/inactive users via filtering.

</specifics>

<deferred>
## Deferred Ideas

None — discussion stayed within phase scope. Multi-date-field selectability and preset shortcuts ("Last 7 days") were considered and explicitly rejected for this phase to keep UI minimal.

</deferred>
