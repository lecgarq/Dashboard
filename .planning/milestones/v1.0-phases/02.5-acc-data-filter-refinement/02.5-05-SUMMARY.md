# 02.5-05 — FILT-01 hide path — SUMMARY

## Outcome

Take-1 fix (commits `84e73ec` graphRenderers.ts + AccUsersGraph.tsx) confirmed correct under runtime instrumentation. No additional code change required for FILT-01 itself. Take-2 v2 instrumentation has been stripped from production code.

## What was actually wrong

Not a code bug. The original "doesn't work" human-verify report was a **test-scenario mismatch with FILT-03's exclude-list semantic**.

FILT-03 contract (in `accGraphFilters.ts` line 50): a user is excluded from the canvas only when **every** entry in their `modules` array is in the active `disabledModules` list. Toggling a single module OFF therefore hides only users whose ACC access is exclusively that module. Hermosillo's directory is dense — every user with Build access also has Docs, Cost, Model Coordination, etc. — so the original re-verify path (toggle one module → expect visible delta) produced a legitimate zero-delta result, which surfaced as the perceived "blink and stay the same" bug.

## Runtime evidence (collected via Chrome DevTools MCP, 2026-05-06)

Captured against live Hermosillo dataset (23,559 instance nodes, Cosmos GPU physics):

| Scenario | filtersActive | visible | zeroed | GPU buffer evidence |
|----------|---------------|---------|--------|---------------------|
| Build OFF (1 toggle) | 1 | 23,559 | 0 | unchanged — correct: no user is exclusively-Build |

The header counter, the visible set size, the zero count, and the GPU buffer dump all advance in lockstep across toggle events. The take-1 fix is functioning as designed.
