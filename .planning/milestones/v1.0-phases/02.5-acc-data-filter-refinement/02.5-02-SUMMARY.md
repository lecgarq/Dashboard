# Phase 02.5 Plan 02: Filter Logic Rewrite Summary

One-liner: Rewrote GraphFilters with disabledModules/companyRoles/dateFrom/dateTo, extracted pure nodeMatchesFilters to accGraphFilters.ts, wired URL query-param persistence with drag-defer guard, and locked down behavior with 28 Vitest tests.

## What Was Built

### accGraphFilters.ts (new pure module)

Extracted `GraphFilters` interface, `DEFAULT_FILTERS`, `FilterableNode` interface, and `nodeMatchesFilters` into a dedicated pure module. This is the canonical implementation — `AccUsersGraph.tsx` imports from it rather than redefining.

**Why extracted:** `AccUsersGraph.tsx` is `"use client"` and pulls in React hooks, Next.js navigation, and Cosmos.gl — none of which work in Vitest's node environment. A clean extraction keeps the filter logic testable in isolation.

### nodeMatchesFilters — four filter dimensions

| Dimension | Semantic | Plan ref |
|---|---|---|
| `roles` | include-list (unchanged) | — |
| `lastAddedBuckets` | include-list (unchanged) | — |
| `adminAccess` | enum (unchanged) | — |
| `disabledModules` | exclude-list: excluded only when ALL modules are disabled; no-modules nodes always pass | FILT-03 |
| `companyRoles` | include-list: empty = all; null companyRole maps to "Unspecified" | DATA-01 |
| `dateFrom` / `dateTo` | inclusive ISO date range; null lastSignIn excluded when range active | FILT-02 |

### URL query-param persistence

- On mount: `useState(() => readFiltersFromUrl(searchParams))` seeds filters from URL.
- On change: `useEffect([filters])` with 300ms debounce calls `writeFiltersToUrl` via `router.replace(..., { scroll: false })`.
- Only non-default values are written to URL (short URLs).
- `isFirstUrlWriteRef` skips the echo-back on initial mount.

**URL param keys:** `roles`, `moff`, `croles`, `from`, `to`, `admin`.

### Drag-defer guard

`pendingFiltersRef` stores filter changes that arrive mid-drag. After `pointerup` clears `isDraggingNodeRef`, the pending filters are applied via `rebuildVisibleIndices()`.

### filterOptions shape update

`filterOptions.modules` renamed to `filterOptions.moduleOptions`; new `filterOptions.companyRoleOptions` added (distinct `companyRole ?? "Unspecified"` values, sorted alphabetically).

### activeFilterCount

Memoized count of active filter dimensions — available for plan 04's "Showing X of Y" header.

### localStorage

`acc-graph-filters` localStorage key is entirely removed. Verified: `grep -r "acc-graph-filters" app/` returns zero matches.

**2. Note on "recursive cascade" in rebuildVisibleIndices**
- The plan describes a cascade that hides project/role/module nodes when all their connected user nodes are hidden. However, `nodesRef.current` only contains `UserNode` instances — project/role/module hub nodes exist only inside `accGraphOrganicLayout` as topology helpers and are never stored in the main nodes array. The "cascade" for user-only node arrays is identical to the base pass (all nodes are user kind). The existing `rebuildVisibleIndices` correctly filters all nodes and posts visibility to the worker. No structural change was needed here — cascade across hub nodes will be wired in plan 03 when the renderer receives hub-node visibility.
