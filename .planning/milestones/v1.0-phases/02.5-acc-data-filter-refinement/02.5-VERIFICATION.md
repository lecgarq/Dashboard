### FILT-01 Root Cause Investigation Guide

The user observed no visual change when filters are applied. The code path is:

```
filter state change
  → useEffect fires
  → rebuildVisibleIndices() (new Set<number> built, visibleIndexSetRef.current replaced)
  → cosmosRendererRef.current?.setVisibleIndices(visibleIndexSetRef.current)
     → identity check: visibleSet !== lastVisibleSet → passes
     → buildPointSizes Float32Array with zeros for excluded indices
     → graph.setPointSizes(sizes)
     → graph.render?.()
```

**Suspected root causes in priority order:**

1. **cosmosRendererRef.current is null when filter effect fires.** The optional-chain `?.` silently no-ops the entire call. Add a temporary log immediately before line 1202 to confirm the ref is populated: `console.log('[FILT-01-debug] cosmosRendererRef', !!cosmosRendererRef.current, visibleIndexSetRef.current.size)`. If it logs `false` or the wrong size, the renderer isn't ready when filters first change.

2. **draw() overwrites the zeroed sizes on the next rAF frame.** After `setVisibleIndices` uploads zeroed sizes, the rAF loop calls `draw()` every 16ms. If any code in `draw()` triggers the `nodeCount !== lastNodeCount` branch (e.g., on initial data load, which may race with the first filter application), `draw()` calls `setPointSizes(buildNodeSizeBuffer(...))` which resets ALL nodes to full size — and does not null `lastVisibleSet`. On the next filter change, the new Set reference passes the identity check again and zeroes are uploaded, but the following `draw()` immediately overwrites them if node count changes. Reproduce by logging in the `nodeCount !== this.lastNodeCount` branch.

3. **Cosmos GPU-physics mode ignores setPointSizes.** When `usePhysics=true`, Cosmos owns the simulation and may ignore external buffer writes mid-simulation. Verify by checking whether `setPointSizes` has any effect while the GPU simulation is running — may need to pause the simulation before uploading and resume after.

4. **lastVisibleSet stale reference across renderer re-init.** `lastVisibleSet` is only reset in `destroy()`. If the renderer is recreated (via `CosmosGraphRenderer.create()`) without calling `destroy()` on the old instance first, the new instance starts with `lastVisibleSet = null` (correct), but if the same renderer ref is reused after re-init without calling `destroy()`, `lastVisibleSet` may hold the old Set. Check whether the renderer is ever re-initialized without going through `destroy()`.

5. **frame.userIndices used by the Canvas2D backend.** The Canvas2D edge-skip gate reads from a `Set<number>` built from `frame.userIndices`. Verify that `frame.userIndices` is populated from `instIdxRef.current` (which rebuildVisibleIndices updates), not from a separate array that the physics worker populates independently.
