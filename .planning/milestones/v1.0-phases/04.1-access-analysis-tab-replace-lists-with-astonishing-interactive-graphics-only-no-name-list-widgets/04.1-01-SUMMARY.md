## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] DashboardFindings field names corrected in `isSelectionValid`**
- **Found during:** Task 3 (selectionContext reconciliation)
- **Issue:** Plan's `<interfaces>` block referenced `findings.junkFindings` / `findings.duplicateFindings` / `findings.outliers`, but the real interface in `lib/acc/dashboardAnalytics.ts` uses `junkRoles` / `duplicateRoles` / `outlierCombos`. Implementing literally would not compile.
- **Fix:** Wrote `isSelectionValid()` against the actual `DashboardFindings` shape (`junkRoles`, `duplicateRoles`, `outlierCombos`). Identity keys preserved per plan intent (`role` for junk; `roleA + roleB` for duplicate; `moduleSet.join(",")` for outlier).
- **Files modified:** app/(dashboard)/users/dashboard/selectionContext.tsx
- **Commit:** 4aee565

**2. [Rule 3 - Blocking] `useSeverityColor` return type widened**
- **Found during:** Task 2 typecheck
- **Issue:** `as const` on the LIGHT and DARK maps produces incompatible literal-type narrowings (`"#EF4444"` vs `"#FF6B6B"`). The conditional `dark ? DARK : LIGHT` widened to never-typeable union.
- **Fix:** Declared `SeverityColorMap = Readonly<Record<"HIGH"|"MEDIUM"|"LOW", string>>` and used it as the hook return type. The two raw constants remain `as const` for callers that want literal types via inference; the hook returns the wider, unified type.
- **Files modified:** app/(dashboard)/users/dashboard/widgets/_shared/dashboardTokens.ts
- **Commit:** 921e272
