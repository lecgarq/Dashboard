  <files>app/(dashboard)/users/sphere3d/clusterAssignment.ts, sphere3d/__tests__/clusterAssignment.test.ts</files>
  <behavior>
Export `UNASSIGNED_CLUSTER_ID = 0`.

Export `assignClusterIds(nodes: AccGraphInstanceNode[]): { ids: Int32Array; keyByCluster: string[] }`:
- For each node: key = `node.companyRole ?? node.roles[0] ?? null`.
- null/empty → cluster id 0.
- Otherwise: assign sequential cluster ids starting at 1, keyed by lowercased trimmed key. Stable across calls (sorted insertion order by first-seen index).
- Returns `Int32Array(nodes.length)` of ids + a `keyByCluster` array where index = cluster id, value = original-cased key (or "" for id 0).

Export `buildClusterCentroids(clusterCount: number, opts?: { seed?: string; sphereRadius?: number }): Float32Array`:
- Returns a `Float32Array` of length `clusterCount * 3` — xyz per cluster.
- Cluster id 0 sits at the origin (0,0,0) — unassigned blob at center.
- Clusters 1..clusterCount-1 spread on a Fibonacci-sphere at `sphereRadius * 0.7` (gives clusters breathing room inside the volume).
- Uses seedrandom factory when seed is provided so tests are deterministic. (Import from `./deterministicMode` is allowed but optional — for Fibonacci-sphere distribution no RNG is needed.)

Cases (RED → GREEN):
- Two nodes with same companyRole "Acme" → same cluster id (not 0)
- Node with companyRole=null and empty roles → id 0
- Node with companyRole=null but roles=["Architect"] → falls back to "architect" cluster
- "Acme" and "acme" produce the same cluster id (case-insensitive)
- buildClusterCentroids(5) returns Float32Array length 15, index 0 is (0,0,0), all other clusters are at distance ~`sphereRadius * 0.7 ± 0.001` from origin
- Two centroids from a 10-cluster table are ≥ some minimum separation (Fibonacci distribution sanity)
  </behavior>

Two pure functions, no DOM, no react. Vitest config already exists (`vitest.config.ts` is in the project). Place tests next to source under `__tests__/`. Use existing test pattern from `cosmosUtils.test.ts` for setup style.
  </implementation>
