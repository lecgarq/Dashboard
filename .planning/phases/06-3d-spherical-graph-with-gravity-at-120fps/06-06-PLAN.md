  <action>
BillboardLabels.tsx ("use client"):
- Props: `{ nodes: AccGraphInstanceNode[]; physics: PhysicsApi; maxVisible?: number /* default 50 */; lodDistance?: number /* default 10 */ }`.
- Mount a FIXED pool of `maxVisible` drei `<Billboard><Text/></Billboard>` (RESEARCH Pattern 4 — recycle, do not mount/unmount). Each pool slot has a ref.
- Maintain a CPU array of node positions: every 8 frames (debounce per Pattern 4), read positions for a candidate set via CPU readback IS expensive — alternative: maintain a CPU mirror updated by a sparse readback of the position texture on a slow cadence (e.g., 2Hz), OR sample positions through a CPU-side cheap re-simulation skipped. RECOMMENDED simpler approach: every 8 frames, do a 1-time `gl.readRenderTargetPixels` on the FULL position render target into a Float32Array buffer (size 4 × textureWidth² ≈ 410KB at 25k) — yes it's a sync stall, but at 8-frame cadence it's amortized. Profile and document.
- Each cadence tick:
  1. Compute distance from camera to each node position (CPU loop on the mirrored Float32Array).
  2. Pick top `maxVisible` whose distance < lodDistance.
  3. Assign their positions + names to the pool slots; mark unused slots `visible=false`.
- Hide labels entirely under `?replay=1` (variance source).

If the readback stall measurably hurts frame budget, fall back to a labels-disabled mode with a console warning and a SUMMARY note. Phase verification gate is interactive fps; labels are nice-to-have if perf-marginal.
