## Boundary-risk resolution (REQUIRED reading — resolved with evidence, do NOT widen scope)

Roadmap SC#1 says "All `includePermissionSummary` consumers ... AND terrain files read from
`AccFolderPermissionSummary`." Investigation shows the projection genuinely serves ONLY the
summary aggregate, NOT the terrain:

- **The summary path** (`acc-hot-cache.ts:304-317`) builds a per-`(projectId, roleId)` rollup
  Map `{ folderCount, totalBytes, permTypes[] }`. This is EXACTLY the shape of
  `AccFolderPermissionSummary` (byte-identical backfill, Phase 18). → SWITCHABLE. Do it.
- **The terrain views** (`lib/server/folderPermissionTerrainView.ts:98,171-185`;
  `lib/server/templateFolderTerrain.ts`) read PER-FOLDER, PER-ROLE tier via
  `loadFolderPermRows(projectId, { l2Only })` and map each perm row into a `TerrainCell` keyed
  by `folderId` (with `perm_type`/`n_actions` per folder). `AccFolderPermissionSummary` is a
  per-`(projectId, roleId)` ROLLUP with NO per-folder detail (`folderCount` is a count, not the
  folder ids/tiers). The terrain CANNOT read the projection without losing granularity and
  breaking the TEST-02 golden masters. → OUT OF SCOPE, with evidence. Terrain stays on Phase 15's
  `folderPermQuery.ts` / its raw `$queryRaw`. Do NOT touch terrain files in this plan.

So "terrain files read from AccFolderPermissionSummary" in SC#1 is a conflation of the two
folder-permission paths; the correct, non-lossy PROJ-02 scope is the single summary aggregate
inside `getCachedAccDcBulkUsers`. This plan touches NO terrain source. If a future milestone
wants a per-folder terrain projection, that is a new (per-folder) model — a deferred seed, not
Phase 19.

Note on "consumers": `AccessAnalysisShell.tsx:507`, `RightPanelStack.tsx:109`,
`acc-route-hydration.ts:56`, `scripts/build-instance-features.ts:43`, and the prewarm task
(`acc-hot-cache.ts:917`) all just CALL `bulkUsers({ includePermissionSummary: true })` — they
funnel through `getCachedAccDcBulkUsers`. The data-source swap is entirely internal to that one
function; those call sites do NOT change (verified: their inputs are unchanged, only the branch
implementation changes).

Workshop-impact note: renders identically. Internal data-source swap only — no `app/` route,
component, chart, theme, or WebGL change; `/users/spatial-graph` untouched.

Data-truthfulness note: the projection inherits the live aggregate's coverage boundary exactly
(`folderCrawlStatus IN ('ok','partial')` is baked into the Phase 18 backfill). No new metric,
no hidden gap — a proven byte-identical mirror.
