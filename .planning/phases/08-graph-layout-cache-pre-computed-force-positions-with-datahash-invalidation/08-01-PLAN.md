  <action>
Append the following model to the END of `prisma/schema.prisma`, after the `AccMemberCache` model block:

```prisma
model AccGraphLayoutCache {
  id        String   @id @default("singleton")
  positions Float[]
  dataHash  String
  nodeCount Int
  updatedAt DateTime @updatedAt
}
```

Design rationale (per RESEARCH.md):
- `id @default("singleton")` — fixed primary key enforces exactly one row; upsert pattern is safe
- `positions Float[]` — Prisma maps to PostgreSQL `float8[]`; mirrors the `LodEmbedding.vector Float[]` precedent already in schema
- `dataHash String` — sha256 hex fingerprint of all AccMemberCache rows (computed server-side in getGraphLayout)
- `nodeCount Int` — safety check used by consumer before applying cached positions (guards against node count mismatch)
- `updatedAt @updatedAt` — auto-updated by Prisma on every upsert; useful for debugging staleness

After editing schema.prisma, run the migration using the DIRECT Supabase connection (port 5432), NOT the pooler URL (port 6543). The pooler rejects prepared statements used by Prisma's schema engine (documented pitfall in STATE.md Phase 6 Plan 01):

```bash
DATABASE_URL="$(grep DIRECT_URL .env | cut -d'=' -f2-)" npx prisma migrate dev --name add_acc_graph_layout_cache
```

If `DIRECT_URL` is not in `.env`, check for `DATABASE_URL_DIRECT` or inspect `.env` for the port-5432 connection string. The direct URL bypasses pgbouncer pooler.

After migration succeeds, regenerate the Prisma client:
```bash
npx prisma generate
```
