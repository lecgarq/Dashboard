<objective>
Repair the raw-project-GUID leak in `lib/server/folderActivityView.ts` `loadFolderActivityProjects()`, the function behind the "Folder Activity by Role" panel on `/access-analysis`. This is the owner-flagged folded-in scope under the TRUTH-01 theme ("show the truth legibly").

Today (verified): line ~51 builds the name map from `db.accDcProject.findMany(...)` (550 projects) ONLY, and line ~58 falls back to `nameById.get(r.projectId) ?? r.projectId` — so any project in the ~956-project activity set that is NOT in the 550-project DC set renders its raw GUID. Fix = ALSO merge names from the live `AccProject` table (1,153, the superset); if a name still cannot be resolved, render the literal "Unknown project" instead of the GUID.

`loadFolderActivityTree()` in the same file does NOT use project names (it groups by folder + actor) — leave it untouched. The only consumer of `loadFolderActivityProjects` is `loadFolderActivityProjectsAction` (`app/(dashboard)/access-analysis/folderActivityActions.ts`), which returns `ProjectActivityTotal[]` unchanged in shape — so this fix is a pure internal behavior change with no caller-signature impact.

Purpose: the presenter can point to the "Folder Activity by Role" view in the live demo and see real project names (or an honest "Unknown project"), never a raw GUID.
Output: a corrected `loadFolderActivityProjects` with merged name resolution + a graceful fallback, plus a Vitest pinning the pure transform.
</objective>
