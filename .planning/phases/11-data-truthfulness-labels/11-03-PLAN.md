Surface the ACCDS ~12-month data floor on the Activity-over-time timeline (TRUTH-02, CONCERNS §2.6). Add a `dataFloor` to the `loadActivityTimeline()` RSC response and render (a) an account-wide "Data available from [Mon YYYY]" caption under the timeline and (b) the per-project floor in the chart hover tooltip.

Verified anchors:
- `lib/server/activityTimelineView.ts` `loadActivityTimeline(force)` is a **server-only RSC, NOT a tRPC procedure**. Its CTE `astart` (lines ~29-33) already computes `SELECT "projectId", MIN("createdAt") AS s FROM "AccActivityAccds" GROUP BY "projectId"`, but that per-project minimum is currently used only as a backfill boundary and is never returned. Today the function returns `ActivityTimelineRow[]`.
- The ONLY runtime caller is `app/(dashboard)/access-analysis/mainCharts.tsx` (it destructures the array into `timelineRows`). The Vitest `app/(dashboard)/access-analysis/page.test.tsx` mocks it as `vi.fn(async () => [])`. Both MUST be updated when the return shape changes — this is the CONTEXT "check all callers before changing the shape" VERIFY item.
- The timeline UI chain is: `mainCharts` → `AccessAnalysisCharts` (computes `timelineSummary` via `summarizeActivityTimeline`) → `ActivityTimelineChart` (renders the EChart + a `timeline-headline` muted caption + an axis-trigger HTML tooltip formatter). `ActivityTimelineChart` already reads `useTheme()` and uses `cAxis`/`cTitle` resolved colors — reuse those for the new caption/tooltip line.

Purpose: the presenter can state, and point to, the date from which activity data exists (and the per-project floor on hover) — making the ~12-month ACCDS history limit visible instead of implied.
Output: a `dataFloor`-carrying `loadActivityTimeline` return, threaded props, a month-year caption, a per-project tooltip line, and a Vitest on the pure floor aggregation.
