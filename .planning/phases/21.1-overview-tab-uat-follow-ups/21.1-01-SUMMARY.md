## Decisions Made
- **Umbrella services (docs/sheets/bridge) never override an already-mapped verb result** — only rescue an Unmapped one. This preserves the intentional Design Collaboration/Datum/Admin Actions verb refinements research identified (e.g. the ~8,107-row docs-serviceGroup-to-Admin-Actions population), matching the locked CONTEXT.md decision's "Claude's Discretion" clause that lets research corrections override a literal "service always wins" reading.
- **`attributedBy: "service"` fires on agreement too, not just on override/rescue** — because the caveat's honest split is about "did a recognized service tag inform this row," not "did the service tag change anything." This makes `attribution.serviceCount` track service *coverage*, and the movement matrix in `21.1-ATTRIBUTION-DELTA.md` is the separate, correct place to report actual reclassification.
- **The diagnostic script's interpretation text is regenerated dynamically from the live movement matrix**, not hardcoded to the research doc's framing — an earlier draft copy-pasted 21.1-RESEARCH.md's "concentrated in Design Collaboration/Data Management/Admin Actions boundary calls" language, which this specific live run's movement matrix (Unmapped->Data Management, Data Management->Build) did not actually show. Caught during self-review before committing; fixed to report only what the run's own numbers demonstrate.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Pre-existing `toEqual()` pin tests broke on the additive `attributedBy` field**
- **Found during:** Task 1 (running `npx vitest run lib/acc/activityClassification.test.ts` after adding the field)
- **Issue:** The plan states the additive field keeps "existing callers/tests... passing unchanged," but Vitest's `toEqual()` performs strict deep-equality, so 4 pre-existing pin assertions (`classifyActivity("issue-attach")`, `("create-project")`, `("add-member")`, `("totally-unknown-action-xyz-999")`) failed once the extra key appeared, even though `moduleId`/`label`/`category` were unchanged.
- **Fix:** Added `attributedBy: "verb"` to each of the 4 existing `toEqual()` expected objects (the correct, byte-identical value for the service-omitted path).
- **Files modified:** `lib/acc/activityClassification.test.ts`
- **Verification:** `npx vitest run lib/acc/activityClassification.test.ts` -> 19/19 passed
- **Committed in:** `e0f0c976` (Task 1 commit)

**2. [Rule 1 - Bug] `ModulesPieChart.test.tsx` fixtures failed tsc after `ModuleSummary.attribution` became required**
- **Found during:** Task 2 (running `npx tsc --noEmit` after adding the `attribution` field to `ModuleSummary`)

- **Fix:** Added `attribution: { serviceCount, verbCount }` to both fixtures (`0/197` for the populated fixture matching its existing all-null-service rows, `0/0` for the empty fixture).
