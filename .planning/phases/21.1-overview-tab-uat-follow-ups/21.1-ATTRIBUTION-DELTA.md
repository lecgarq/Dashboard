## Interpretation

Movement is real but small (order of 0.0040% of total activity). The
live movement matrix above shows the actual shape of this run, not a hypothetical:
- **Unmapped -> Design Collaboration**: 125 rows (0.0026%).
- **Unmapped -> Data Management**: 41 rows (0.0009%).
- **Data Management -> Build**: 21 rows (0.0004%).
- **Unmapped -> Build**: 1 rows (0.0000%).

Most of this is the Unmapped rescue (a previously-Unmapped rawAction resolved by a recognized
service tag), plus a small number of decisive-service overrides (e.g. a rawAction that verb-classified
to Data Management but carries an `issues`/`submittals`/`rfis`/`admin` service tag, so service wins).
The much larger ~8,107-row `docs`-serviceGroup-to-Admin-Actions population 21.1-RESEARCH.md measured
is an UMBRELLA service (docs/sheets/bridge) deferring to an already-correct, more granular verb
refinement — by design (locked decision) it produces **zero** module movement here, because the
verb taxonomy's Design Collaboration / Datum / Admin Actions splits are intentional, not bugs, and
an umbrella service never flattens them back to Data Management.

This is **not** a Model Coordination reclassification — that was already fixed 2026-06-05 by
commit `6164cfae`, which redirected all `issue-*` verbs to Build and excluded Model Coordination
from the donut entirely. `docs/activity-module-audit.md`'s "~966 Model Coordination" figure is stale
(untracked, predates that commit) and is superseded by this live evidence — it should not be
cited going forward.

The service-attributed/verb-inferred split above (99.98% / 0.0180%)
is the live figure the Overview tab's TRUTH-03 caveat should state (wired in plan 21.1-04), replacing the
stale "~40.7% disagreement" framing (that number was always `AccActivity`'s population rate, not
a disagreement rate).

## Owner-delegated mapping review (21.1-04 checkpoint)

At the plan 21.1-04 Task 3 checkpoint (live `:3100` preflight, 2026-07-06), the owner reviewed the
"Activity by module" panel and questioned two specific action groups (`publish-entity`,
`create-version-set`), then delegated the full module-attribution mapping review: *"I'll hand that
to you — review the types of activities and the modules assigned, use your best effort."*

The orchestrator audited all 122 live `(rawAction, service)` combinations against the Autodesk ACC
module boundaries and applied 4 taxonomy corrections in `lib/acc/activityClassification.ts`. Row
volumes below are from a direct live-DB query against the same per-`(project, action, service)`
aggregate this script uses (4,722,412 total activities):

| # | Correction | Actions | Live rows | % of total |
|---|---|---|--:|--:|
| 1 | `sheets` service rescue-target: Data Management -> Design Collaboration | `view-sheet-public-link` (66), `create-public-link-for-sheets` (59) | 125 | 0.0026% |
| 2 | Publish/version-set workflow unified to Design Collaboration | `publish-entity` (51), `create-version-set` (16), `add-version-to-set` (13), `rename-version-set` (0), `update-version-set` (0) | 80 | 0.0017% |
| 3 | `notify-final-members`: Admin Actions -> Data Management (Docs review-workflow sibling) | `notify-final-members` (48) | 48 | 0.0010% |
| 4 | `add-folder-naming-standard`: Unmapped/docs-rescue -> Datum (naming-standard family) | `add-folder-naming-standard` (19) | 19 | 0.0004% |
| | **Total** | | **272** | **0.0058%** |

Rationale detail:

1. Every verb-mapped `sheets` action (`view-sheet`, `publish-sheet`, `export-sheet`,
   `delete-sheet`, `print-sheet`, `shared-with-recipients-for-sheets`) already resolves to Design
   Collaboration. The `sheets`-umbrella rescue path (for the two actions above, absent from the
   excel catalog) previously landed in Data Management instead — inconsistent with every other
   sheets action. `sheets` stays in `UMBRELLA_SERVICES` (it still never overrides an
   already-mapped verb result — see the movement matrix: this run's live "Unmapped -> Design
   Collaboration: 125" row is exactly this correction in action).
2. `publish-entity`, `create-version-set`, `add-version-to-set` were the owner's specific
   checkpoint questions. All three (plus the sub-1-row `rename-version-set` /
   `update-version-set` family members, included for taxonomy coherence) are part of the same
   publish/version-set workflow as `publish-sheet` (already Design Collaboration) — moved there
   for consistency. `restore-version` (Docs file-versioning) and `create-set` (Docs Sets feature)
   were deliberately NOT moved; they are a different Docs feature, not part of the
   publish/version-set workflow.
3. `notify-final-members` is filed under Preconstruction in the excel catalog (which the
   classifier redirects to Admin Actions), but its purpose is a Docs review-workflow
   notification step — its siblings `notify-reviewers` / `submit-review` / `claim-review-task`
   are all Data Management. Moved to Data Management for family consistency.
4. `add-folder-naming-standard` has no excel catalog entry (was `Unmapped`, rescued to Data
   Management by the `docs` umbrella service). Given an explicit mapping to Datum, the same
   module as `apply-naming-standard` and `add-attribute-to-naming-standard`, unifying the
   naming-standard family.

**Net effect on the Overview donut:** ~272 rows (~0.006% of total activity) move module. The
"Activity by module" donut's Design Collaboration slice grows by ~205 rows (items 1+2, both
moving OUT of Data Management), Data Management has a net change of -157 (-205 from items 1+2,
+48 from item 3), Admin Actions shrinks by 48 (item 3, moving to Data Management), and Datum grows
by 19 (item 4, moving out of the Unmapped/docs-rescue path — Unmapped total is unaffected since
these rows were already rescued to a real module before this review). The service-attributed/
verb-inferred caveat split (99.98% / 0.0180%) does not change materially — none of these 4
corrections change whether a row is `attributedBy: "service"` vs `"verb"`, only which module a
service-attributed or verb-attributed row lands in.
