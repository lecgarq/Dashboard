<decisions>
## Implementation Decisions

### Scope
- **All 3 items are in Phase 21.1** — owner confirmed. Item 1's recorded deferral reason
  (products→ModuleId vocabulary alignment) is already solved by `reduceModules`; the
  Future-Requirements "provisioned-vs-active module coverage" seed is superseded by this
  phase's item 1 to the extent it covers the grants-per-module chart.

### Activity-by-module data-bug (item 2)
- **Service-first fix**: where `AccActivity.service` is populated, it wins module attribution;
  the `classifyActivity` verb taxonomy remains the fallback for rows without service data.
- Donut numbers are expected to change — that is the point; the owner flagged the numbers.
- The ⓘ caveat updates to state the attribution split honestly (X% service-attributed,
  Y% verb-inferred) — live figures, never hardcoded.
- Research must verify whether `AccActivityAccds` has a service-equivalent column; if not,
  accds rows stay verb-classified and the caveat's split must reflect that.

### Provisioned-modules chart (item 1)
- **Member grants, horizontal bars**: one bar per module; value = member×project grants with
  access (`AccProjectMember.products` via `reduceModules`), scoped to the selected projects.
- Click a bar → drill list of top projects for that module (existing drill-list conventions).
- Sits on the Overview tab as the "provisioned" half of the provisioned-vs-used story next to
  the activity donut.

### Activity share by project donut (item 3)
- **Top 10 + Other**; click a project slice → that project's module breakdown, derived
  client-side from the per-`(project, rawAction)` rows the Overview already loads
  (`loadModuleActivity`) — no new loader for the drill.
- The synthetic "Account-level" bucket is **excluded** from the donut and noted in the caption.
- The existing Top-projects-by-activity chart stays unchanged (additive request).

### Placement
- The two new panels render as a **side-by-side 2-up row between "Activity by module" and
  "Ingest freshness"**: Activity share by project + Provisioned modules. The activity story
  stays contiguous at the top; provisioning reads as its own beat.

### Claude's Discretion
- Exact SQL shape for the grants-per-module aggregate (bounded, server-side), loader
  eager-vs-lazy choice, skeleton/empty-state composition, bar/donut color assignment from the
  resolved theme, drill-list row caps, and how the module-attribution fix is layered
  (classifier-level vs loader-level) so all consumers stay consistent — provided every locked
  decision above holds.

</decisions>
