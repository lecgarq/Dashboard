<objective>
Build the pure data + logic substrate for the widened dimension aperture on
`/users/spatial-graph` (= `/users/access-analysis` shell): (1) add the owner-chosen
palette dimensions to the catalog as node-level `CatalogDimension`s, (2) band every
continuous dimension into LABELED tiers, and (3) expose honest, node-derived coverage
per dimension. No picker is widened yet (that is 25-02), so no UI or invariance-test
content changes here — this plan is non-breaking foundation.

Purpose: DIM-01 requires grouping by any of the ~14 already-computed node dims, and
DIM-05 requires honest coverage labels. Both need a single, banded, coverage-aware
catalog before Group-by/Color-by/Filter can draw from it. Continuous dims (risk,
permission strength, folder breadth, accessible-data TB, activity volume) MUST band —
today `valueKeyLabel`'s ordinal branch only handles `permission`/`tenure`/activity-family
ids, so any other ordinal collapses to one "None" bucket (verified in
`dominantClusters.ts:97-111`). Coverage MUST be derived from the real snapshot, not a
hardcoded figure — the "~48%" used in discussion is illustrative and unverified.

Output: `dimensionBands.ts`, `dimensionCoverage.ts` (+ tests), widened
`dimensionCatalog.structural.ts`, and banded `valueKeyLabel` in `dominantClusters.ts`.
</objective>
