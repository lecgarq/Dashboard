<objective>
Make the `/users/spatial-graph` toolbar filter draw from the unified dimension aperture and
work as add-a-chip: the presenter picks a dimension from a menu (themed, coverage-labeled),
then multi-selects which VALUES to keep, and non-matching nodes filter out — composing across
multiple filtered dimensions. This retires DIM-04's third divergent list
(`SliderContext.DIMENSIONS`, 12 registry dims) so all three controls resolve from one source.

Purpose: DIM-04 requires filtering by any available dimension from the toolbar, using the
same aperture Group-by/Color-by use — and the owner chose add-a-chip multi-select-to-keep
over an always-visible chip wall (anti-overbloat). Filter values must be the SAME banded
categories the other two controls show, so a "Risk: High" filter matches the "High" blob.
DIM-05 coverage labels attach to the dimension menu here.

Boundary note: `usePredicateEngine.buildMaskPredicate` and `filterSelectionByPredicate` are
pure and heavily tested. Widen `featureValueForDim` ADDITIVELY (catalog-aware resolution with
the legacy 6-id switch as fallback) so existing predicate tests stay green; do not rewrite the
predicate body.

Output: catalog-native filter values, dynamic aperture-keyed FilterContext, add-a-chip Toolbar
menu + multi-select value chips.
</objective>
