`/users/spatial-graph`. Both pickers resolve from the Phase-24 unified
`PRESET_DIMENSION_IDS` (no second array), now widened to the full owner palette and
organized by themed optgroups (Identity · Activity · Risk · Permission, with role/project/user

both derive their option list from the same `PRESET_DIMENSION_IDS` (Phase-24 DIM-03 decision).
Widening it necessarily widens both pickers at once; splitting them across waves would leave
the color picker rendering options it cannot color. So group + color ship together. DIM-05
coverage labels attach to both pickers here.

Boundary note (CONCERNS.md — large route-owned access-analysis modules): these dimension
modules already live under the app route; this plan edits them in place and does NOT expand
the boundary. The `lib/` migration of this cluster is out of scope for this phase.

Output: widened `dimensionIdSpace.ts`, catalog-native banded color in `AccessAnalysisShell.tsx`,
themed + coverage-labeled selects, active-dim caveat badge, updated `groupByDimensions.test.ts`.
</objective>
