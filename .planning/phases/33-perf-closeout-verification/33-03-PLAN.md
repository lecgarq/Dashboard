## Working hypothesis (verify by profiling, do not assume)

At Tier 0 every node carries ambient motion, so the overlay's parked-frame
skip (`!moved`) never triggers — 14,200 `quadraticCurveTo` Path2D rebuilds +
up-to-9 batch strokes run every ~33 ms tick. Candidate levers (apply only
what profiling ranks highest and appearance-safe):

- Skip rebuild for edges whose endpoints moved sub-pixel (ambient orbits are
  micro-motions; a per-edge or coarse dirty check may park most of the web).
- Straight-line segments below a screen-length threshold where the bezier is
  visually indistinguishable (must be appearance-identical at normal zoom —
  if in doubt, don't).
- Reduce per-tick allocation (reuse Path2D? Path2D is append-only — reuse
  means fewer objects per tick, e.g. one path per band instead of
  bucket×band when stroke color can be batched differently WITHOUT changing
  rendered colors — only if colors truly identical per batch).
- Lower overlay tick rate under ambient-only motion (e.g. 30→20 Hz) — ONLY
  if visually imperceptible; bands/opacities unchanged.
