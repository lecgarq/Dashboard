## The two regressions (both reproduced, both deterministic)

### PERF-04 — +42% time-to-graph regression (frozen path)
- **Measured 8822 ms** median time-to-graph-rendered vs Phase-24 baseline **6193.2 ms**
  (gate ~6812 ms = baseline +10%). Δ = **+2628.8 ms / +42.4%**. First-paint 956 ms vs 644 ms.
- **Apples-to-apples:** identical cosmos.gl 3.3.0, identical `NEXT_PUBLIC_ACC_GRAPH_TEST=1`
  frozen static-layer path, identical `scripts/measure-spatial-graph-baseline.cjs` (N=5),
  identical 22,279 nodes. The ONLY delta from the baseline build is **Phases 25 (aperture) +
  26 (catalog wall) + 27 (force-anchor layout revival)**.
- Baseline build = commit `33d6e58f` (Phase 24). Regressed build = commit `20d72f49`
  (Phase 27 deployed HEAD).
- **Suspect:** the widened dimension surface adds per-load cost even on the frozen path —
  candidates: catalog-target/weight building (`buildCatalogTargets`/`buildCatalogWeights` at
  `AccessAnalysisShell.tsx:575-579`, run every load per the v2.4 audit), the 208-dim
  catalog/slider state init, or Phase-27 layout wiring that now runs work formerly gated off.
  **Bisect 25/26/27** to localize; the frozen path (`createStaticLayer`) should be cheap.

### PERF-03 — default 2D lasso fails 3/3 warm-cache (selection-commit race)
- **Fails at `tests/e2e/acc-dc-graph.spec.ts:603`**: `waitForFunction(() =>
  getSelectedNodeIds().length > 0)` times out at 15 s. The lasso *projects and locates* the
  dense region fine (cloud + dense point **byte-identical across all runs**: cloud=1841×1731
  n=22279, dense=(372,282), probeCount ~4750) — so this is **NOT camera drift, NOT the
  documented 120 s load-flake** ([[project_lasso_e2e_load_flake]]). The drag runs over correct
  coords; the selection just never commits.
- **Tell:** the warm-up (first) load PASSED and selected 4747/22279; all subsequent warm-cache
  loads fail to commit. A **post-`mouse.up()` selection-commit race** that only mis-fires on
  faster (warm) loads.
- **Suspect:** Phase 27's layout-engine revival (force-anchor / reheat-guard / "General"
  default / strongest-wins organic anchor) changed the timing/handshake between the lasso
  `mouse.up` and the selection commit. The memory note records F1 made this green warm-cache on
  a **pre-v2.4** build. Trace the commit path: `GraphCanvas2D.tsx` lasso handling →
  `findPointsInPolygon`/selection state → `getSelectedNodeIds` bridge (`graphTestBridge.ts`),
  and whether a static-layer refit or reheat-guard now clears/defers the selection.
