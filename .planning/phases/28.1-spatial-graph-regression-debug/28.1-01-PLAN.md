<objective>
Fix PERF-03 at its root cause in the product path (NOT the test). The default 2D lasso fails
to commit its selection warm-cache because `LassoOverlay`'s pointer-listener `useEffect`
(`LassoOverlay.tsx:159`) depends on `onComplete` — which is a fresh inline arrow every shell
render (`AccessAnalysisShell.tsx:457`, `onLassoComplete={(indices) => {...}}`) — plus
`hitTest`/`onDragStart`/`onDragEnd`. Any shell re-render between pointerdown and pointerup
re-runs the effect; its cleanup (`LassoOverlay.tsx:154-156`) resets `drawingRef.current=false`
and `pathRef.current=[]` mid-drag, so `onUp`'s `if (!drawingRef.current) return` early-exits
and `onComplete` is never called. `getSelectedNodeIds()` (which reads the RAW `lassoSelection`
via `setShellTestState`) stays empty → the e2e times out at `acc-dc-graph.spec.ts:603`.

This fragility is LATENT (identical in the Phase-24 baseline; Phase 27 did not touch
LassoOverlay/GraphInteractions). Phase 27's layout-engine revival newly triggers it by adding
post-freeze re-renders that now land during the drag window on fast (warm-cache) loads —
which is why the first (cold) warm-up run passes and every warm run fails.

The fix makes an in-progress drag immune to ALL re-renders by subscribing the pointer
listeners once per `active` and reading the live callbacks through refs. No test is weakened,
no timeout raised, no lasso/physics/freeze behavior changed.
</objective>
