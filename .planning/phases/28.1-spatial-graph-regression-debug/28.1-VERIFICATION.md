# Phase 28.1 Verification — Spatial-Graph Regression Debug

Both regressions found by Phase 28's verification are root-caused at the narrowest shared
boundary and fixed in the product path (not masked in the test); both PERF gates re-run green.

## Requirement coverage

### PERF-03 — default 2D lasso selection-commit race (28.1-01, commit `716ee966`)
- **Root cause:** `LassoOverlay`'s pointer-listener `useEffect` depended on the inline
  `onComplete` arrow (`AccessAnalysisShell.tsx:457`), a fresh identity every shell render; any
  mid-drag re-render re-ran the effect, whose cleanup reset `drawingRef`/`pathRef`, so `onUp`
  early-returned and the selection never committed. **Latent since the Phase-24 baseline**
  (byte-identical there; Phase 27 never touched the file) — Phase 27's post-freeze re-renders
  newly trigger it on warm-cache loads.
- **Fix:** latest-ref pattern; the effect keys on `[active]` only and reads live callbacks via
  refs (`LassoOverlay.tsx`), so an in-progress drag survives any re-render and commits on
  pointerup. Fixes all callers, not one closure.
- **Evidence:** red-first unit test (RED→GREEN) added to `__tests__/LassoOverlay.test.tsx`;
  `tests/e2e/acc-dc-graph.spec.ts:537` **3/3 warm-cache GREEN** on `:3100` (4795/4747/4747 of
  22279), spec unmodified — the identical run that failed 3/3 in 28-02. **Success criterion 2 met.**

### PERF-04 — +42% time-to-graph regression (28.1-02, staged, uncommitted)
- **Discovery:** test-flag-gated boot-boundary instrumentation + a single `:3100` build localized
  the cost. The entire effect-entry→graph build/render span is **317 ms**;
  `buildCatalogTargets`/`buildCatalogWeights` = **86 ms** — the widened v2.4 surface is NOT the
  regression. The cost was two pre-existing infra items upstream of the build effect: the
  `dynamic()` shell-chunk parse gap and a client `bulkUsers`+`instanceEmbedding` refetch (~2.3 s).
- **Root cause of the refetch:** `createServerSideHelpers({ transformer: superjson }).dehydrate()`
  returns a superjson-**wrapped** `{ json, meta }` state; the App Router passed it straight to
  `<HydrationBoundary>`, which expects a raw `DehydratedState`, so the boundary hydrated nothing
  and the shell refetched the multi-MB payload on mount. (SSR-HTML inspection proved the payload
  was present, `status:"success"`, hashes matching — so not auth/key/prefetch failure.)
- **Fix:** `app/(dashboard)/users/spatial-graph/page.tsx` — `superjson.deserialize(...)` the
  dehydrated state before the boundary, guarded on the `{ json }` wrapper. Scoped to this one
  route. A first attempt (client `QueryClient` `serializeData`/`deserializeData`) was proven
  ineffective and reverted to net-zero.
- **Evidence:** committed `scripts/measure-spatial-graph-baseline.cjs`, N=5, frozen path, `:3100`,
  cosmos 3.3.0 → **median time-to-graph-rendered 4360 ms** (runs 4190/4273/4360/4512/4518),
  firstPaint 720 ms, nodeCount/featureCount 22279. **≤ 6812 ms gate → PASS** (also −30% vs the
  6193.2 ms baseline; data integrity preserved). Post-fix probe confirmed the `bulkUsers` client
  fetch is **absent on all 5 runs**. **Success criterion 1 met.**
