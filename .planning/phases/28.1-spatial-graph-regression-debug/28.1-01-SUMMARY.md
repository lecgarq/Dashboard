# 28.1-01 Summary — PERF-03 Lasso Selection-Commit Race (root-caused + fixed)

## Root cause (superpowers:systematic-debugging, CONFIRMED before any fix)

The default 2D lasso failed to commit its selection warm-cache (`acc-dc-graph.spec.ts:603`
timeout, 3/3 in 28-02) because of a **re-subscribe race in the product path**, not a test flake:

- `LassoOverlay`'s pointer-listener `useEffect` depended on `[active, hitTest, onComplete,
  onDragStart, onDragEnd]` (`LassoOverlay.tsx:159`, pre-fix).
- `onComplete` is a **fresh inline arrow every shell render** — `AccessAnalysisShell.tsx:457`
  `onLassoComplete={(indices) => { setLasso(indices); setLassoActive(false); }}`.
- So **any shell re-render between pointerdown and pointerup** re-ran the effect. Its cleanup
  (`LassoOverlay.tsx:154-156`) resets `drawingRef.current = false` and `pathRef.current = []`
  **mid-drag**. The subsequent `onUp` hits `if (!drawingRef.current) return` and **never calls
  `onComplete`** → `setLasso` never fires → `lassoSelection` stays empty.
- Proof it's the commit (not geometry): the bridge's `getSelectedNodeIds()` reads the **RAW**
  `lassoSelection` (`graphTestBridge.ts:542` ← `setShellTestState({ selection: lassoSelection })`
  at `AccessAnalysisShell.tsx:332`), so an empty result means `setLasso` was never called. The
  28-02 evidence (cloud + dense point byte-identical every run, probeCount ~4750) already ruled
  out camera/geometry/load-flake.

**Latent, not Phase-27-authored:** the dep array and the inline `onLassoComplete` are
**byte-identical in the Phase-24 baseline** (`33d6e58f`), and Phase 27 never touched
`LassoOverlay.tsx` / `GraphInteractions.tsx` (`git log 33d6e58f..20d72f49 --` on both = empty).
Phase 27's layout-engine revival newly **triggers** the latent bug by adding post-freeze
re-renders that now land during the drag window on fast (warm-cache) loads — which is exactly
why the first (cold) warm-up run passed and every warm run failed.

## Fix (narrowest shared boundary — LassoOverlay only)

Latest-ref pattern: the pointer-listener effect now keys on **`[active]` only** and reads the
live callbacks through refs (`hitTestRef`/`onCompleteRef`/`onDragStartRef`/`onDragEndRef`, kept
current by a tiny no-dep effect). A changed callback identity no longer re-runs the effect, so
its cleanup can no longer reset `drawingRef`/`pathRef` mid-drag. An in-progress drag now
survives **any** number of re-renders and commits on pointerup. Every existing guard
(setPointerCapture try/catch, `<3`-point bail, window-level finalizers, drawingRef double-fire
guard, mid-drag-unmount OrbitControls thaw, `active=false` pass-through) is byte-preserved.

Fixes the bug for **all** callers, not just the current shell closure — the correct root-cause
fix rather than stabilizing one inline callback.
