Create `FolderPermissionsWidget.tsx`. Structure:

1. **Data fetch:** `const { data, isLoading } = trpc.accFolders.getMatrix.useQuery({ projectIds: scopedProjectIds }, { staleTime: 5 * 60_000 });` where `scopedProjectIds` derives from `useSelection()` (if inbound selection sets a project/role, scope to that subset).

2. **Local state (the 4 filters + search):**
   - `projectFilter: Set<string>` (multi-select)
   - `roleSearch: string` (also feeds the row/column unified search per CONTEXT)
   - `tierThreshold: PermTier | null` (null = no threshold) + `tierMode: 'gte' | 'eq'`
   - `anomaliesOnly: boolean`
   - `unifiedSearch: string` (search box that filters BOTH rows by folder path AND columns by role name)
   - `expandedFolders: Set<string>` (parent folderIds whose children are visible)

3. **Derived data:**
   - `visibleColumns`: project×role pairs after `projectFilter`, `roleSearch`, `unifiedSearch` (role-name match). Group columns by `projectId`, preserving group order.
   - `visibleRows`: folders after `unifiedSearch` (path match). Collapsed: only `parentId === null` folders. When a parent is expanded, insert its direct children in-place. Rendering is via a flat array of `{folder, depth}` items — easier for the row virtualizer than expanding rows in-place (see RESEARCH Pitfall 5).
   - Cell lookup: build `Map<string, MatrixRow>` keyed by `${folderId}::${roleId}` for O(1) cell render.
   - When `anomaliesOnly`: filter rows to those with any orphanReasons; filter columns analogously (any matching role appears in at least one orphan row).
   - When `tierThreshold`: filter cells (display empty/blank) where `tier < threshold` (use `TIER_ORDER` index from permissionMapping). With `tierMode === 'eq'` only exact tier matches show.

4. **Virtualization (TanStack Virtual v3):**
   ```typescript
   const rowVirtualizer = useVirtualizer({ count: visibleRows.length, getScrollElement: () => parentRef.current, estimateSize: () => 32, overscan: 10 });
   const colVirtualizer = useVirtualizer({ count: visibleColumns.length, horizontal: true, getScrollElement: () => parentRef.current, estimateSize: () => 120, overscan: 5 });
   ```
   Render only `rowVirtualizer.getVirtualItems()` × `colVirtualizer.getVirtualItems()` cells.

5. **Project group headers:** sticky horizontal headers spanning their role columns. Approach: a separate sticky row above the matrix that uses the same `colVirtualizer` positions but groups consecutive same-project columns under one label. Sticky via `position: sticky; top: 0; z-index: 2`. Background must match the dashboard widget surface.

6. **Cell rendering:**
   - Background color reflects tier (use existing dashboard palette; check `RolesModulesHeatmapWidget` for the color ramp pattern).
   - Empty cells = white/transparent.
   - Cells from projects with `projectCrawlStatus !== 'ok'`: render with a stripe overlay + tooltip `"Crawl incomplete — data may be missing"`.
   - Cells with `orphanReasons.length > 0`: desaturated background + `<AlertTriangle className="size-3" />` glyph in corner. Tooltip enumerates reasons.
   - Cells with `mapActions(actions).extended === true`: small `+` badge in opposite corner (visually distinct from `⚠` — use color/position to differentiate, per CONTEXT discretion).
   - **Hover:** show raw `actions` array.
   - **Click:** `setSelected({ kind: 'folderPermission', folderId, folderPath, roleId, roleName, projectId, projectName, permType, actions, orphanReasons })`.

7. **Header clicks (outbound interactivity):**
   - Click role column header → `setSelected({ kind: 'role', roleId, roleName })` if 'role' kind already exists in union; if not, use the existing role-selection convention from RolesModulesHeatmapWidget — mirror, don't invent.
   - Click folder row label → `setSelected({ kind: 'folderPermission', folderId, ..., roleId: '', roleName: '' })` — folder-level selection (or use a separate kind if the row-only selection doesn't fit the cell kind).

8. **Inbound scoping:** `useSelection()` — when `selected.kind === 'role'`, filter `visibleColumns` to that roleId; when `selected.kind === 'project'`, filter to that projectId. Read the existing convention from RolesModulesHeatmapWidget for what selection kinds already cause project/role scoping elsewhere.

9. **Register the widget:** Edit `widgetRegistry.ts`:
   ```typescript
   import { FolderPermissionsWidget } from "./widgets/FolderPermissionsWidget";
   export const WIDGETS = {
     // ...existing 9...
     folderPermissions: { component: FolderPermissionsWidget, title: "Folder Permissions", span: "col-span-2" },
   } as const satisfies Record<string, WidgetSpec>;
   ```
   Add `folderPermissions` to `DEFAULT_ORDER` at the end of the array.

10. **Discretion items** (document choice in 04-06-SUMMARY.md):
    - DOM cells via TanStack Virtual first; canvas only if Plan 07 perf measurement shows DOM can't sustain 60 FPS scroll.
    - Color desaturation curve: use 30% saturation + 60% lightness for orphan cells (match existing dashboard muted treatment).
