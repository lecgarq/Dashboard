  <action>
Add two optional props to `FolderPermissionTerrain`:
- `externalSelectedIds?: string[]` — when provided, the component's candidate
  project selection derives from it instead of internal picker state.
- `hidePickers?: boolean` (default false) — hides `ProjectSelect` and
  `ProjectMultiSelect` (keep `ModeToggle`, `TierLegend`, `DetailPanel` untouched).

Derivation (research §4, runs in a `useEffect` keyed on a stable serialization of
`externalSelectedIds`, only when the prop is provided):
- length 0 → `setMode("overview")` (CONTEXT.md's locked empty-state: all-folders overview,
  never a blank pane).
- length 1 → `setMode("single")`; `setSingleId(that id)`.
- length ≥ 2 → `setMode("compare")`; `setSelected(topStaffed.filter(id =>
  externalSet.has(id)).slice(0, 6))` — the existing top-staffed ranking intersected with
  the external selection, capped at the existing default of 6. If the intersection has < 2
  entries (selected projects lack terrain options), fall back to "single" on the first
  intersecting id, or "overview" when the intersection is empty.
- Also call the existing `clear()` on derivation change (same as the current picker
  handlers do).
- After the derived default, the user may still use ModeToggle to switch modes; a manual
  mode change must keep using the externally-derived candidate lists (singleId = first
  intersecting top-staffed id; compare list as above). Extract the derivation into a small
  exported pure helper `deriveTerrainSelection(externalIds: string[], topStaffed:
  string[]): { mode: Mode; singleId: string; selected: string[] }` at the top of the file
  so it is directly unit-testable.
- When `externalSelectedIds` is undefined, behavior must be byte-identical to today
  (internal useState defaults, pickers visible unless `singleProject`).
- Document the "Compare tab vs compare mode" naming distinction in a comment above the
  new props.

Do not touch any other file. `npx tsc --noEmit` after.
