# Phase 20.1 Plan 02: Permission Volume By Level (PERM-01 reframe) Summary

Built the unmounted PERM-01 reframe slice — a bounded server aggregate, top-N+Other
transform, and stacked-bar chart that answer the owner's verbatim UAT question
("which role has the most admin permissions out of all") by counting folder
permissions per role, segmented by the verbatim ACC-stored permission level, with
zero touch of the byte-sized footprint chart it will replace.

## What Was Built

**Task 1 — `lib/server/permissionLevelView.ts` + server action.** A bounded
`$queryRaw` `GROUP BY (f."projectId", fp."roleId", fp."permType")` over
`AccFolderPermission` JOIN `AccFolder` (live-verified 60,110-row output). Own
query, deliberately NOT routed through `lib/server/folderPermQuery.ts`'s
`loadFolderPermRows` — that module's header forbids single-use additions and
returns per-folder rows, not this pre-aggregated shape; this is a different
consumer of the same base table, same precedent as the Ph18 backfill script.
`permType` passes through verbatim (never imported/remapped via
`lib/acc/permissionMapping.ts`'s `PermTier`). `folderCount` is `COUNT(*)::int`
from Postgres — already a plain JS number, no BigInt boundary. 5-minute TTL
cache (standard sibling pattern). `permissionLevelActions.ts` is an auth-gated
`"use server"` wrapper mirroring `folderTerrainActions.ts`.

**Task 2 — `app/(dashboard)/access-analysis/permissionLevelCounts.ts`.**
`summarizePermissionLevel` groups rows by role into `{ total, byLevel,
projectCount }` bars, sorted by total desc (tiebreak roleName), top-10 kept +
"Other (N roles)" collapse (aggregated `byLevel`, no drill entry — matches
`summarizePermissionFootprint`'s convention). `PERMISSION_LEVEL_ORDER` fixes the
6 live stored values strongest->weakest; any unrecognized `permType` value is
appended after them, alphabetically — honest passthrough, never dropped.

**Task 3 — `PermissionLevelChart.tsx`.** Horizontal ECharts stacked bars: one
bar per role (top-10 + Other), one `bar` series per level present with `stack:
"levels"`, x-axis is a plain integer folder-permission count
(`.toLocaleString()`, no `formatBytes` — bytes are gone from this headline
chart per the locked decision). Colors are a 6-stop sequential intensity ramp
(red = Full Controller, sky = View Only) indexed to `PERMISSION_LEVEL_ORDER`;
unrecognized levels fall back to a neutral zinc tone. Native ECharts legend
shows verbatim level names. Clicking a role's bar (`onEvents.click`,
`params.name` = roleName) opens a per-role project drill list, identical UX
structure to `PermissionFootprintChart`'s drill panel; the "Other" bar is
non-drillable. Empty state renders "No permission data for this view." A muted
caption keeps the View Only skew honest: "Counts folder-permission grants by
level, from the live folder-permission table (View Only dominates
account-wide)."

Component is **not mounted anywhere** — plan 20.1-06 wires it into the Roles
tab in place of `PermissionFootprintChart`, per the phase's locked IA.

## Data Truthfulness

- `permType` values are the raw ACC-stored strings (6 live values verified in
  research: View Only 5,917,818 / View+Download 60,802 /
  View+Download+Upload+Edit 48,761 / View+Download+Upload 11,059 / Full
  Controller 2,145 / Upload Only 25) — never remapped through
  `permissionMapping.ts`'s `PermTier` vocabulary, which uses different label
  text ("Full administrative controls" vs. "Full Controller") for a
  differently-derived classification. Both `permissionLevelCounts.test.ts` and
  `PermissionLevelChart.test.tsx` assert the PermTier label never appears.
- Any future unrecognized `permType` string is kept and rendered (appended to
  `levels`, colored with a neutral fallback), never silently dropped.
- The chart's own caption states the View Only skew honestly instead of hiding
  it behind an even-looking stacked bar.
