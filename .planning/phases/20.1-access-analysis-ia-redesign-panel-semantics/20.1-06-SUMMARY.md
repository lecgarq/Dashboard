## Decisions Made

- **Ref-flag fetch gating, not a null-check** (Rule 1 — bug prevention): the
  plan's task text described the fetch condition as "if null", but a
  no-session loader result is legitimately `null` and would otherwise
  re-trigger the fetch (and its loading skeleton) every time the tab is
  revisited. A `useRef<boolean>` per slice, set `true` before the fetch call
  fires, preserves the plan's intended fetch-once-then-cache behavior in that
  case too, without changing any test-visible behavior for the happy path.
- **Panel-presence gate moved from a data prop to the loader function prop**
  (`loadActivityRecency`/`loadPermissionLevel`/`loadFolderScopedActivity`
  presence, not `rows` presence) — this matches the pre-existing
  `loadTerrain`/`loadOverview` (Compare tab) convention already in the shell,
  rather than introducing a second, inconsistent gating pattern.
- **New Users-tab table built inline, no new component file** — the plan's
  `files_modified` list named only `UsersTabPanel.tsx` for this surface, so
  the column defs / search / DataTable wiring live there directly, reusing
  `template-mty`'s `TemplateMembersTableShell` pattern verbatim rather than
  extracting a new shared component the plan didn't scope.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fetch-gating condition changed from `rows === null` to a ref flag**
- **Found during:** Task 1, while implementing the lazy-fetch effect
- **Issue:** The plan's task text says "fetch activity-recency + permission-level if null" and separately "Null-result (no session) → keep null". Taken literally, this means the effect's own guard condition (`rows === null`) would remain true forever after a no-session fetch, causing every subsequent tab revisit to refetch (and briefly re-show the loading skeleton) instead of caching.
- **Fix:** Added a `useRef<boolean>` per lazy slice, set to `true` immediately before the fetch call, and gated the effect on that ref instead of on `rows === null`. The resulting rows (`T[] | null`) are still stored and passed straight to the panels unchanged, satisfying "Null-result (no session) → keep null and let panels show their empty states" — but the fetch itself now truly fires "at most once per page load", satisfying "Cache means switching back never refetches" for every outcome, not just the happy path.
- **Files modified:** `app/(dashboard)/access-analysis/components/AccessAnalysisCharts.tsx`
- **Verification:** New test "fetches activity-recency + permission-level exactly once on first Roles-tab activation, and caches on revisit" and the analogous Companies-tab test assert `toHaveBeenCalledTimes(1)` after two round-trips; both pass.
- **Committed in:** `d1464001` (Task 1 commit)

**2. [Rule 1 - Bug] `page.test.tsx` needed new mocks for the three lazy action modules**
- **Found during:** Task 2, running the module-scope test check
- **Issue:** `mainCharts.tsx` now imports `activityRecencyActions.ts`, `permissionLevelActions.ts`, and `folderActivityByCompanyActions.ts` directly (to pass as function props). `page.test.tsx`'s existing route test activates the Roles tab (for its pre-existing roles-donut assertion), which now also fires the shell's lazy-fetch effect for those three unmocked modules — a direct, unavoidable mechanical consequence of Task 1's mainCharts.tsx rewiring, not a pre-existing failure.
- **Fix:** Removed the now-dead mocks for `@/lib/server/permissionFootprintView`/`@/lib/server/signInRecencyView`; added mocks for `./activityRecencyActions`, `./permissionLevelActions`, `./folderActivityByCompanyActions` (each resolving to `[]`), mirroring the existing `./folderTerrainActions`/`./coordinationActions`/`./folderActivityActions` mock pattern already in the file.
- **Files modified:** `app/(dashboard)/access-analysis/page.test.tsx`
- **Verification:** `npx vitest run "app/(dashboard)/access-analysis/page.test.tsx"` → 2/2 passed.
- **Committed in:** `a5b66641` (Task 2 commit, bundled with the deletions since both are the same mechanical fix)
