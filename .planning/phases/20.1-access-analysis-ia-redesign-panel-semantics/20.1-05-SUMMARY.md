## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Radix Tabs.Trigger activation requires `mouseDown`, not `click`, in jsdom**
- **Found during:** Task 3, first `vitest run` of the migrated test suite (24/33 failing)
- **Issue:** The plan's suggested test-migration pattern (`await userEvent.click(screen.getByRole("tab", ...))`) assumes a full pointer-event sequence. Using `fireEvent.click` alone (the pattern actually available, see deviation 2) does not activate a Radix tab in jsdom, because `@radix-ui/react-tabs`'s `Trigger` calls `context.onValueChange(value)` from its `onMouseDown` handler (verified by reading `node_modules/@radix-ui/react-tabs/dist/index.mjs`), not `onClick`. `fireEvent.click` dispatches only a `click` event, not the preceding `mousedown`.
- **Fix:** Built the `openTab()` test helper around `fireEvent.mouseDown(trigger, { button: 0 })` instead of `fireEvent.click`. Isolated the root cause first with a standalone throwaway sanity test (`zzz-tabtest.test.tsx`, deleted after confirming) before applying the fix across the real suite.
- **Files modified:** `app/(dashboard)/access-analysis/__tests__/AccessAnalysisCharts.test.tsx`, `app/(dashboard)/access-analysis/page.test.tsx`
- **Verification:** `npx vitest run "app/(dashboard)/access-analysis"` → 51/51 files, 432/432 tests passed
- **Committed in:** `2594c8bb` (Task 3 commit)

**2. [Rule 3 - Blocking] `@testing-library/user-event` is not an installed dependency**
- **Found during:** Task 3, before writing any test code
- **Issue:** The plan text explicitly suggests `await userEvent.click(...)` for tab activation. `grep` of `package.json` confirms only `@testing-library/dom` and `@testing-library/react` are installed — no `user-event` package. Installing it would add a new npm dependency, which the phase's CONTEXT.md explicitly forbids ("no new npm dependencies").
- **Fix:** Used `fireEvent.mouseDown` (already imported/used throughout the existing suite) instead of introducing the new package. Package-install auto-fixes are excluded from Rule 3 by policy (slopsquatting risk) — this is the inverse case (avoiding an unnecessary install entirely), so no `checkpoint:human-verify` was needed.
- **Files modified:** `app/(dashboard)/access-analysis/__tests__/AccessAnalysisCharts.test.tsx`
- **Verification:** `package.json` confirmed no `user-event` dependency exists; test suite green using only already-installed `@testing-library/react`/`dom`.
- **Committed in:** `2594c8bb` (Task 3 commit)

**3. [Rule 1 - Bug] `page.test.tsx`'s roles-donut route test broken by the shell rewrite**
- **Found during:** Task 3, running `npx vitest run "app/(dashboard)/access-analysis"` (module-scope check per the plan's `<verification>` block)
- **Issue:** `page.test.tsx`'s "buckets single role, Multiple roles, and Unknown" test asserted both the roles-donut `echart` (now on the Roles tab, inactive by default) and the "Activity by module" text (Overview tab, default) in the same render without any tab navigation — a direct, mechanical consequence of Task 2's shell rewrite, not a pre-existing failure.
- **Fix:** Reordered the assertions (check Overview-tab content first, since it needs no click) and added one `fireEvent.mouseDown(getByRole("tab", {name: /roles/i}), {button: 0})` before the roles-donut assertions.
- **Files modified:** `app/(dashboard)/access-analysis/page.test.tsx`
- **Verification:** `npx vitest run "app/(dashboard)/access-analysis/page.test.tsx"` → 2/2 passed
- **Committed in:** `2594c8bb` (Task 3 commit, bundled with the rest of the test migration since both are the same mechanical fix)
