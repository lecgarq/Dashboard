## Key → label mapping (whySimilar.ts, pinned)

`resolveWhyKey(key, center: NodeFeatureSnapshot, match: NodeFeatureSnapshot | undefined)`
→ `{ label: string, coverageDimId?: string } | null`.

Token keys (value embedded in the key — render from the key, snapshots corroborate):

| Key prefix | Chip label | coverageDimId |
|---|---|---|
| `role:X` | `Same role: X` | — |
| `company:X` | `Same company: X` | `company` (DC-sourced) |
| `perm:X` | `Same permission tier: X` | `permissionTier` |
| `permstr:N` | `Same permission strength (N/5)` | `folderAccessPermissions` |
| `act:X` | `Similar activity: X` | `activityVolume` |
| `recency:X` | `Same activity recency: X` | `activityRecency` |
| `aff:X` | `Both X` | — |
| `status:X` | `Same status: X` | — |
| `admin:1` | `Both project admins` | — |
| `admin:0` | null (non-signal — skip) | — |
| `mod:X` | `Shared module: X` (resolve display name via existing module catalog helper if one exists — inspect lib/acc/modules.ts first, else raw key) | — |
| `cov:X`, `*_missing` | null (defense in depth; python already excludes) | — |

Numeric-column keys (value NOT in the key — render live values from both snapshots):

| Key | Chip label (center/match values) | coverageDimId |
|---|---|---|
| `activityTotal` | `Similar activity volume: {a}/{b}` (raw counts, compact-formatted) | `activityVolume` |
| `folderBreadth` | `Similar folder breadth: {a}/{b} folders` | `folderBreadth` |
| `accessibleDataBytes` | `Similar data reach: {a}/{b}` (byte-formatted — reuse an existing formatter if present, inspect first) | `accessibleDataTB` |
| `membershipAgeDays` | `Similar tenure: {a}/{b} days` | `membershipTenure` |
| `permissionStrength` | `Similar permission strength: {a}/{b}` | `folderAccessPermissions` |
| `riskScore` | `Similar risk score: {a}/{b}` | — |

Coverage rule: when `coverageDimId` is set, chip carries a small coverage
suffix/tooltip using `dimensionCoverage(features, dimId)` → `coverageText()`
(computed once per dim id, memoized upstream in the shell and passed down — the
panel stays pure). Permission-derived keys (`perm:`, `permstr:`,
`permissionStrength`, `folderBreadth`, `accessibleDataBytes`) are suppressed
when EITHER endpoint snapshot has `permissionCoverage === "unknown"`.

## Tasks

1. **`whySimilar.ts`** (new, pure): `resolveWhyKey` per the table + a
   `whyCoverageDimIds` export (the set of dim ids chips can reference, for the
   shell's memoized coverage map). Unit tests: every prefix, numeric keys with
   both snapshots, unknown key → null, `cov:`/`_missing`/`admin:0` → null,
   permission suppression on unknown coverage.

2. **`NeighborMatchesPanel.tsx`** — redesign, still pure/presentational:
   - Props: `matches: NeighborMatch[]`, `twins: NeighborTwins` (types imported
     from `lib/acc/embedding/neighborPayload`), existing `indexByNodeId`,
     `features`, callbacks, plus `coverageByDim: ReadonlyMap<string, string>`
     (dimId → coverageText, prebuilt by shell).
   - Match row: name · project (existing join) + score + up to 3 why-chips
     (small zinc `bg-muted` pills; coverage suffix in `text-muted-foreground`).
   - Twin chip under the header when `twins.count > 0`:
     `"{count} identical twins"` — native `<details>`-style expand (or a plain
     useState toggle, ≤200ms, no animation needed) listing capped members
     (snapshot join, click → `onSelectMatch(idx)`), then `+N more` static line
     when `count > ids.length`.
   - Renders null when `matches.length === 0 && twins.count === 0`.
   - Keep width modest (w-64 → w-72 acceptable); overflow-y for long content.

3. **`AccessAnalysisShell.tsx`** wiring:
   - `neighborsQuery.data` is now the typed payload: panel gets
     `matches={data?.matches ?? []}` `twins={data?.twins ?? {count:0, ids:[]}}`.
   - `neighborIndices` builds from `data?.matches` only.
   - Memoized `coverageByDim` from `whyCoverageDimIds` × `dimensionCoverage(features, id)`.

4. **`NeighborMatchesPanel.test.tsx`** (jsdom, follow the style of existing
   component tests in this tree — inspect `embeddingMapSeam.test.tsx` first):
   twin chip renders count, expand lists members + `+N more`, twin click
   re-isolates, why-chips render resolved labels with coverage suffix,
   suppressed chip absent for unknown-coverage node, old-shape-equivalent input
   (`why: []`, `twins.count 0`) renders the plain list without crashing.

5. **Design gate**: this touches a visual surface — run `impeccable detect` on
   the panel change per the phase-planning rule; record the result.
