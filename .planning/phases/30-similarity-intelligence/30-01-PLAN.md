## Payload contract (v2 — pinned here)

```json
{
  "v": 2,
  "matches": [
    { "nodeId": "user::proj", "score": 0.8731, "why": ["company:ACME", "act:High", "activityTotal"] }
  ],
  "twins": { "count": 12, "ids": ["user2::proj", "..."] }
}
```

- `matches`: exactly `min(K_NEIGHBORS, distinct_groups - 1)` entries, ranked by
  cosine score desc. Each match nodeId is the FIRST member (input order) of a
  distinct dup-key group. `score` rounded 4dp as today.
- `why`: up to 3 dimension keys, contribution-share desc. May be shorter when
  fewer than 3 dimensions have positive contribution.
- `twins.ids`: capped at `TWIN_ID_CAP = 10` (matches the owner's ~10; group-size
  distribution printed at runtime justifies or revises in the SUMMARY).
- Old rows (bare `[{nodeId, score}]`) remain in the DB until the next live run —
  the proc normalizes them (plan 30-02); python never writes the old shape again.

## Tasks

1. **Twin groups + representative kNN** (`compute_instance_embeddings.py`)
   - New pure fn `twin_groups(dup_keys)` → `(group_of_row: np.int64[n], members: list[list[int]])`
     built from the existing `hybrid_dup_keys` output (dict first-seen order —
     deterministic).
   - New pure fn `structured_neighbors(hybrid, node_ids, dup_keys, k=K_NEIGHBORS, twin_cap=10)`:
     - Build unique matrix `U = hybrid[first_row_of_each_group]`.
     - `NearestNeighbors(n_neighbors=min(k+1, n_groups), metric="cosine")` on U;
       query U (same guard style as `knn_neighbors`).
     - Per node i (group g): matches = neighboring groups ≠ g, take k, nodeId =
       `node_ids[members[h][0]]`, score = `round(1 - dist, 4)`.
     - twins: `count = len(members[g]) - 1`, `ids = [node_ids[j] for j in members[g] if j != i][:twin_cap]`.
     - Returns `{nodeId: payload_dict}` with `"v": 2`.
   - Keep `knn_neighbors` only if still referenced by tests; otherwise delete it
     and its test (it has no other caller — verify with rg before deleting).

2. **Why-contribution derivation** (`compute_instance_embeddings.py`)
   - New pure fn `top_contribution_keys(vec_a, vec_b, dim_keys, top=3, exclude=...)`:
     elementwise product of the two (sparse) rows; share = product / dot; take
     top-3 positive-contribution keys, skipping keys ending `_missing` and keys
     starting `cov:`. `dim_keys = vocab + num_cols` (column order of
     `build_hybrid_matrix` — TF-IDF block first, numeric block second; the
     numeric block is scaled inside `build_hybrid_matrix`, so compute
     contributions on the HYBRID rows, not the raw blocks).
   - Wire into `structured_neighbors` per match (representative vectors — twin
     members are byte-identical so representative math is exact for every member).
   - `main()`: pass `vocab + num_cols` through; print twin-group distribution:
     `twin-groups=<G> singleton=<s> max=<m> median=<md> p95=<p>`.

3. **Tests** (`scripts/test_compute_instance_embeddings.py`)
   - `test_twin_groups_exact_vector_only` — distinct numerics split otherwise
     identical tokens (mirrors `test_hybrid_dup_keys_distinguish_numerics`).
   - `test_structured_neighbors_distinct_matches_and_twin_summary` — small seeded
     fixture with one 3-member twin group + distinct rows: matches contain no
     same-group member, count/ids/cap correct, self excluded, k fill correct.
   - `test_structured_neighbors_twin_cap` — group larger than cap → ids capped,
     count still exact.
   - `test_top_contribution_keys_math` — 2 hand-built dense rows: assert the
     returned keys equal a manual numpy `(a*b)/np.dot(a,b)` argsort; assert
     `_missing` / `cov:` exclusion; assert ≤3 and positive-only.
   - `test_structured_neighbors_payload_shape` — v field, score rounding, why
     length bound.
   - Full suite: `python -m pytest scripts/test_compute_instance_embeddings.py -q` green.
