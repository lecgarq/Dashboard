<objective>
Close UAT gap 4 (Stable badge never appears on the Cosmos GPU renderer — the production default).

Root cause (per .planning/debug/stable-badge-not-appearing.md): The Cosmos stability-polling useEffect at AccUsersGraph.tsx:1170-1194 reads `cosmosRendererRef.current` synchronously and bails when null. Its deps `[isReady, isSimStable]` don't include any signal for when the async `CosmosGraphRenderer.create(...).then(...)` resolves and assigns the ref (around line 896). Typical timing: `setIsReady(true)` fires before Cosmos init resolves, the polling effect runs once, sees null, and silently exits — never reinstalling the interval.

The Canvas2D fallback path is also dead in Cosmos mode (worker effect early-returns at line 1080-1083 when renderBackend === "cosmos", so `hasReceivedTickRef.current` is never set on the Cosmos path), but that's by design — the Cosmos polling effect IS the Cosmos detection path. We just need to make it actually run.

Fix: Promote the renderer-readiness signal to React state. Add `cosmosReady` boolean state, set it true immediately after `cosmosRendererRef.current = renderer` at line 896, and include it in the polling effect's deps array.

Purpose: UI-02 actually works for the WebGL2 user population.
Output: cosmosReady state, immediate setter call after Cosmos init, updated effect deps, cleanup-on-destroy resets the flag.
</objective>
