<per-dim-target-derivation>
<!-- Resolves RESEARCH Open Question #2 -->

mathLayer's `computeTargetPositions` returns a SINGLE Float32Array(n*3) for the combined slider state — NOT per-dim arrays. The physics layer needs per-dim per-axis arrays for `forceX/Y/Z` accessors.

Resolution (Option a from RESEARCH): During physicsLayer construction, for each dimension `d` in `dims`, call `computeTargetPositions(features, dims, sliders_d)` where `sliders_d` has 1.0 at dim `d` and 0.0 elsewhere. Then split the resulting Float32Array(n*3) into per-dim `{ x: Float32Array(n), y: Float32Array(n), z: Float32Array(n) }`.

This reuses Phase 1's API with zero changes. The caller computes targets ONCE at construction; slider changes only mutate force.strength(), not targets.
</per-dim-target-derivation>

REQUIRED CONSTANTS (locked decisions):

- `ALPHA_MAX_REHEAT = 0.3`
- `STRENGTH_AT_ONE = 0.1` (d3 forceX/Y/Z default at slider=1)
- `REPULSION_ZERO = -10`, `REPULSION_ONE = -60`
- `DECAY_ZERO = 0.1` (fast freeze), `DECAY_ONE = 0.02` (slow decay)
- `SKIP_THRESHOLD = 0.02` (no-reheat optimization)
- `VELOCITY_DECAY = 0.4`

REQUIRED BEHAVIOR (each maps to a phase requirement):

**PHYS-01 — Named forces:** For each `dimId` in `dimNames`, register THREE forces: `sim.force(\`${dimId}-x\`, forceX(d => targets[dimId].x[d.index!]).strength(0))` and same for `-y`/`-z`. Initial strength is 0 (sliders start at 0). Plus `sim.force("repulsion", forceManyBody().strength(REPULSION_ZERO))`. NO `forceCollide`, NO `forceCenter`.

**PHYS-02 — Reheat pattern:** `updateSliders(values)` computes `maxSlider = Math.max(0, ...Object.values(values))`, calls `force.strength(sv * STRENGTH_AT_ONE)` on each dim's x/y/z named force, mutates `manyBody.strength(lerp(REPULSION_ZERO, REPULSION_ONE, maxSlider))`, sets `sim.alphaDecay(lerp(DECAY_ZERO, DECAY_ONE, maxSlider))`, then `sim.alpha(Math.min(maxSlider, ALPHA_MAX_REHEAT)).restart()`. NEVER call `sim.restart()` bare. Unpin nodes (`fx=fy=fz=null`) before reheat.

**PHYS-03 — Continuous engine params:** The three engine params (alpha, alphaDecay, manyBody.strength) are mutated atomically inside `updateSliders` BEFORE the reheat. `prevMax` is updated AFTER the reheat for the next call's no-reheat optimization.

**PHYS-04 — Mask bus isolation:** `setMask(predicate)` is a pure mutation: loop `i=0..nodes.length`, write `_alphaMask[i] = predicate(i)`, then `_maskVersion++`. It MUST NOT reference `sim`, `manyBody`, or any d3 symbol. Add an inline comment: `// PHYS-04 invariant: this method MUST NOT touch the simulation.`

**PHYS-05 — Freeze-on-rest:** Register `sim.on("end", async () => { ... })` BEFORE the cache check. Handler synchronously packs xyz into `Float32Array(nodes.length * 3)`, then `await savePositions(connection, cacheKey, nodeIds, xyz)`, then `sim.stop()`. Set `frozen = true` synchronously at the top of the handler.

**Cache-hit path (Pattern 6):** After registering forces and the end handler, call `loadCachedPositions(connection, hashNodeSetAndSliders(nodeIds, _sliders), nodeIds)`. On hit: write positions into d3 node objects, pin via `fx/fy/fz = x/y/z`, call `sim.stop()`, set `frozen = true`. On miss: seed each node with `Math.random() * 2 - 1` in xyz (range `[-1, 1]^3`), then `sim.restart()`.

**No-reheat optimization:** Inside `updateSliders`, if `frozen && Math.abs(maxSlider - prevMax) < SKIP_THRESHOLD`, skip the reheat (return after param updates). Reference: CONTEXT line 32.

**Pitfall guards:**
- `forceSimulation<SimNode>(nodes, 3)` — second arg MUST be `3` (Pitfall 1). NEVER omit.
- Accessor uses `d.index!` not closure-over-index (Pitfall 3).
- `simulation.alpha(target).restart()` — never `alpha(0)` (Pitfall 4).
- All Float32Arrays are stride-3 (Pitfall 7). `getPositions()` allocates `new Float32Array(nodes.length * 3)`.
