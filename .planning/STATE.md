- **02-01:** Exported `fetchWithRetry` from `lib/server/acc-admin.ts` rather than duplicating APS 429/backoff logic.
- **02-01:** Pagination uses short-page sentinel (`results.length < PROJECT_PAGE_SIZE`); `pagination.totalResults` is unreliable during concurrent APS deletes.
- **02-01:** Soft delete via set-difference (`findMany notIn freshIds` → `updateMany status:inactive`).
- **02-02:** Exported `fetchHqUsers` from `lib/server/acc-admin.ts` — it is the correct fetcher for HQ v1 AND HQ v2 plain-array endpoints (avoid `fetchAccPaged` for HQ v2).
- **02-02:** No soft-delete for `AccRole` in this phase — APS exposes no stable diffable hub-role list; deferred to v2.x CLN bucket.
- **02-02:** `extractAndPersistHubRoles` returns the role array so plan 02-03 can fall back to name→id resolution when per-project industry_roles is incomplete.
- **02-03:** AccProjectRole compound-unique `@@unique([projectId, roleId, memberId])` rejects null in compound where; the unassigned-default-access row (memberId=null) uses findFirst + create/update fallback. Member-linked rows still use the compound upsert.
- **02-03:** `MemberAggregator` (Map<lowercased-email, entry>) is threaded through `runPerProjectFanOut` so plan 02-04 reads a single union map for `accMemberCache` dual-write — no second pass needed.
- **02-03:** `lastSignInPresent` uses key-presence (hasOwnProperty), not value check, so explicit `null` lastSignIn does not false-positive as dropped `?fields=`.
- **02-03:** Product alias map limited to documentManagement/fieldManagement/costManagement per RESEARCH Open Question 3; other product keys pass through unchanged.
- **02-04:** `buildCacheBlob` return-type annotation `: BulkAccUser` is the compile-time safety net for Pitfall 2 (silent zero-nodes if cache shape drifts). Round-trip test (`buildAccGraphSnapshot` consumes synthetic blob) pins runtime compatibility.
- **02-04:** Cache writer is additive-only (no row deletion for absent emails) — Phase 2 partial failures leave yesterday's cache intact; the v1.0 dashboard keeps rendering. Stale rows tolerable; missing rows would zero the graph.
- **02-04:** v2.0 writes `companyRole: null` and `isAccountAdmin: false` for all users (HQ v1 prefetch deferred). Existing UI treats null companyRole as "Unspecified"; `bulkAccSummary` defaults isAccountAdmin to false on legacy rows.
- **02-04:** Rule 1 type fix: widened `ProjectFindFirst.apsHubId` in `lib/server/acc-helpers.ts` to `string | null` to match Prisma's actual return type. Helper's runtime null-check already handled the case; the type was tighter than reality and blocked typechecking `runQuickSync(prisma)`.
- **03-01:** Renamed `AccActivity.action` → `rawAction` — safe because live DB has 0 rows in AccActivity at migration time (verified via PrismaPg adapter count query). projectId stays nullable; Plan 02 will write empty-string sentinel for admin rows so the composite `@@unique([autodeskId, rawAction, createdAt, projectId])` dedup applies (Postgres treats NULL != NULL in unique constraints).
- **03-01:** Hand-wrote `prisma/migrations/20260511151713_acc_activity_v2/migration.sql` because `prisma migrate dev` refuses to run in Claude Code's non-interactive shell. SQL was generated by `prisma migrate diff --from-config-datasource --to-schema --script` and filtered to the AccActivity + UnresolvedAttribution additive changes Plan 01 owns. Applied via `prisma migrate deploy` (non-interactive).
- **03-01:** Rule 3 fix: declared `LodEmbedding.pgvector` as `Unsupported("vector(768)")?` in schema.prisma. The column was added by raw-SQL migration `20260416011500_fix_lod_search_foundation` but never declared in schema, so every new `prisma migrate diff` proposed `DROP COLUMN "pgvector"` on 24,619 rows. The Unsupported declaration surfaces the column to Prisma without changing it.
- **03-02:** Overlap-guard strategy reuses `AccDataConnectorJob.startedAt` as a 60-min stale-lock proxy (no separate `ingestStartedAt` column from Plan 01). A row in `status='running'` started <60 min ago is presumed in-flight; older is reclaimable. Acceptable because only this script ever sets a row to `running`.
